The assignment is asking you to extend your custom Docker image so the Playwright test stage can also use it successfully.

Right now:

```groovy id="r4lnjz"
image 'mcr.microsoft.com/playwright:...'
```

is being used because that image already contains:

* Playwright
* browsers
* Node.js
* dependencies needed for E2E testing

But your custom image currently only contains:

* Node.js
* Netlify CLI
* node-jq

So if you directly switch to:

```groovy id="mjlwmq"
image 'my-playwright'
```

the Playwright stage will fail.

---

# What Is Failing?

The instructor specifically mentions removing:

```bash id="sl0wji"
npm install serve
```

That means:

* `serve` command must already exist inside the image
* just like Netlify CLI now exists globally

So the image must be updated.

---

# What You Need To Do

Your Dockerfile probably currently looks similar to:

```dockerfile id="v6x8xf"
FROM mcr.microsoft.com/playwright:...

RUN npm install -g netlify-cli node-jq
```

You need to add:

```bash id="2p5s0l"
serve
```

to the globally installed packages.

---

# Correct Dockerfile

Most likely solution:

```dockerfile id="8k2n3g"
FROM mcr.microsoft.com/playwright:latest

RUN npm install -g \
    netlify-cli \
    node-jq \
    serve
```

or single-line version:

```dockerfile id="ig55r6"
FROM mcr.microsoft.com/playwright:latest

RUN npm install -g netlify-cli node-jq serve
```

---

# Why This Works

Now your image already contains:

* Playwright
* browsers
* Netlify CLI
* node-jq
* serve

So pipeline stages no longer need runtime installation.

---

# Remove Runtime Installation

Delete:

```bash id="1d8k3i"

```

because `serve` is now globally available.

---

# Important Detail About `serve`

`serve` is usually used to:

* host static frontend files
* run local HTTP server

Playwright E2E tests often require:

```text id="ehnlzm"
Frontend app must be accessible via HTTP
```

So `serve` launches the built frontend locally during tests.

# Important Hidden Concept

Your custom image is becoming:

> a reusable CI platform image

This is exactly how enterprise Jenkins systems operate.

Organizations create internal CI images containing:

* Playwright
* browsers
* kubectl
* AWS CLI
* Terraform
* internal tooling

Then all pipelines reuse those images.

# Why Base Image Still Matters

Your Dockerfile must still use:

```dockerfile id="gd6j85"
FROM mcr.microsoft.com/playwright:...
```

because Playwright images contain:

* Chromium
* Firefox
* WebKit
* browser dependencies
* Linux packages required by browsers

If you switch base image to plain Node.js:

```dockerfile id="6mzn0f"
FROM node:18-alpine
```

Playwright tests will likely fail due to missing browser dependencies.

This is extremely important.

Amazon Web Services is being introduced here as a cloud computing provider and as the platform that will be used throughout the deployment section.

## What AWS Actually Is

AWS provides cloud infrastructure and managed services over the internet.

Instead of:

* buying physical servers,
* building data centers,
* maintaining networking equipment,
* replacing failed hardware,
* and managing power/cooling,

organizations can rent infrastructure from AWS on demand.

AWS operates globally distributed data centers and exposes resources through:

* web consoles,
* APIs,
* CLI tools,
* SDKs,
* and automation systems.

## Pay-as-You-Go Model

AWS mainly follows a consumption-based pricing model.

You are charged based on resource usage such as:

* compute time,
* storage,
* network transfer,
* databases,
* serverless executions,
* monitoring,
* and other services.

This model is important because infrastructure becomes:

* elastic,
* scalable,
* and operational instead of capital expense.

### Virtual Servers

Examples:

* Amazon RDS

* backups,

Usually:

* Amazon S3

Used heavily for:

* backups,

* CI/CD artifacts,

Typically:

* Amazon CloudFront

Used to cache content closer to users globally.

## Why Cloud Adoption Grew Rapidly

The New York Times example illustrates a major cloud advantage:

### Massive short-term compute capability

Instead of buying huge infrastructure for one temporary project:

* they rented cloud compute resources temporarily,
* processed over a million article scans,
* and finished quickly at lower cost.

This demonstrates one of the biggest cloud advantages:

* temporary access to large-scale infrastructure.

Before cloud computing:

* companies often had to over-purchase hardware,
* wait for procurement,
* and maintain idle infrastructure afterward.

Cloud changed this completely.

## AWS Account Creation

The lecture recommends:

* creating a personal account for learning.

AWS requires:

* identity verification,
* and payment method registration.

Even with the free tier:

* AWS still requires a debit/credit card because exceeding limits generates charges.

## AWS Free Tier

AWS provides limited free usage for beginners.

Common free-tier resources include limited:

* EC2 compute,
* S3 storage,
* Lambda executions,
* and databases.

But:

* exceeding limits can generate real costs.

This is why monitoring usage is important.

After account creation, users access:

* the AWS Management Console.

This is the browser-based GUI for AWS services.

From there you can:

* launch servers,
* create storage buckets,
* configure networking,
* manage security,
* monitor infrastructure,

## AWS Regions

AWS infrastructure is divided into geographic regions.

Example:

* US East (N. Virginia)

is one AWS region.

Regions matter because:

* pricing differs,
* latency differs,
* legal/compliance requirements differ,
* and some services/features may vary by region.

The lecture notes:

* US regions are often cheaper than others.

This is generally true because:

* they are older,
* larger,
* and highly optimized AWS regions.

For learning purposes, many people use:

* us-east-1
* because:

  * it is commonly supported,
  * often cheaper,
  * and many tutorials assume it.

## Why Remember the Region

AWS resources are region-specific.

Example:

* an EC2 instance in `us-east-1`
* is separate from one in `eu-west-1`.

This becomes important later for:

* CLI commands,
* Jenkins deployments,
* infrastructure automation,
* and resource lookup.

## Multi-Factor Authentication (MFA)

The lecture strongly recommends enabling MFA.

This is critical.

Without MFA:

* stolen credentials can fully compromise the AWS account.

With MFA:

* attackers additionally need a second authentication factor.

In real-world cloud environments, MFA is considered basic security hygiene.

Especially important for:

* root accounts,
* administrators,
* and production environments.

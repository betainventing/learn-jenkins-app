This lecture is demonstrating the **manual deployment workflow** before automating it with Jenkins.

```text
Human steps → converted into scripted steps
```

# What is being deployed?

A prebuilt frontend artifact:

```text
build/
 └── index.html
```

This `build` directory is the **deployment artifact**.

In real projects, this directory is usually generated by:

```bash
npm run build
```

Examples:

* React → `build/`
* Vite → `dist/`
* Angular → `dist/`
* Next.js static export → `out/`

The build folder contains:

* HTML
* CSS
* JavaScript
* images/assets

These are static files ready to be hosted.

---

# What Netlify is doing

When you upload the `build` folder to Netlify:

1. Netlify receives the files
2. Stores them on its infrastructure
3. Distributes them through a CDN
4. Creates a public URL
5. Serves the files over HTTPS

Effectively:

```text
Local build folder
      ↓
Upload to Netlify
      ↓
Hosted globally
      ↓
Accessible from browser
```

# Manual deployment steps being demonstrated

## Step 1 — Obtain deployment artifact

```text
Download ZIP
↓
Extract ZIP
↓
Get build/ directory
```

This artifact is already production-ready.

---

## Step 2 — Upload artifact

Using Netlify UI:

```text
Deploy manually
↓
Drag & drop build directory
```

This is equivalent to manually publishing a release.

---

## Step 3 — Deployment execution

Netlify performs:

* upload validation
* storage
* CDN sync
* URL generation
* SSL provisioning

---

## Step 4 — Verification

Instructor opens the generated URL to confirm:

* deployment succeeded

* hosting works

This is basic deployment validation.

The instructor explicitly says:

# Why random URLs are created

Netlify auto-generates:

* unique site identifier
* DNS mapping
* public endpoint

Example pattern:

```text
https://random-name.netlify.app
```

This avoids naming collisions.

---

# Why changing site names can fail

The instructor mentions:

> you cannot select every name

Because:

* site names must be globally unique
* another user may already own that subdomain

Example:

```text
myapp.netlify.app
```

may already exist.

# Key deployment terminology

| Term                 | Meaning                                       |
| -------------------- | --------------------------------------------- |
| Build artifact       | Output generated after build                  |
| Deployment           | Publishing application to hosting environment |
| Hosting              | Serving application to users                  |
| Production deploy    | Live publicly accessible version              |
| Static hosting       | Hosting prebuilt HTML/CSS/JS files            |
| Manual deployment    | Human performs deployment steps               |
| Automated deployment | CI/CD system performs deployment              |

# Important technical distinction

This deployment is:

## Static site deployment

Only frontend files are being hosted.

There is:

* no backend server
* no database
* no runtime application server

Netlify is excellent for:

* React apps
* Vue apps
* Angular apps
* documentation sites
* portfolio websites

But not for traditional server-side applications like:

* Spring Boot
* Node.js APIs
* Django apps
* .NET backend services

Those require compute/runtime environments.

# Automation is not GUI interaction

The instructor is correcting a very common beginner misunderstanding.

Jenkins does NOT:

* open Chrome/Firefox
* click buttons
* drag files
* interact with websites visually

That would be browser automation/testing tools like:

* Selenium
* Playwright
* Cypress

CI/CD systems work differently.

They automate systems through:

* APIs
* CLIs
* scripts
* protocols

---

# The correct automation model

Instead of:

```text id="h1v6zn"
Jenkins
   ↓
Open browser
   ↓
Click upload button
```

The real flow is:

```text id="qj0vrx"
Jenkins
   ↓
Run terminal commands
   ↓
Netlify CLI
   ↓
Netlify API
   ↓
Deployment happens
```

This is how most DevOps tooling works.

# What is a CLI?

CLI = Command Line Interface

Instead of using a GUI/web UI, you interact through commands.

Examples:

| Tool       | CLI     |
| ---------- | ------- |
| Docker     | docker  |
| Git        | git     |
| Kubernetes | kubectl |
| AWS        | aws     |
| Netlify    | netlify |

---

# Why CLIs are critical in DevOps

Because:

* scripts can use them
* Jenkins can use them
* pipelines can automate them
* no human interaction required

Without CLI/API access, automation becomes difficult.

# Important issue: global install failure

The instructor hits:

```text id="n9s98n"
permission denied
```

This is extremely common in:

* Docker containers
* Jenkins agents
* Linux CI environments

---

# Why global installs fail in CI/CD

Global npm installs (`-g`) try to write into system directories like:

```text id="dx6h6h"
/usr/local/lib
/usr/local/bin
```

Inside containers:

* current user may not be root
* filesystem may be restricted
* Jenkins user may lack permissions

Result:

```text id="r6e9ct"
EACCES permission denied
```

---

# Correct CI/CD practice

Instead of global install:

```bash id="5zhfmy"
npm install netlify-cli
```

This installs locally inside project:

```text id="tvh75l"
node_modules/
```

---

# Important concept: local binaries

npm packages with executables expose binaries in:

```text id="a4v08z"
node_modules/.bin/
```

So Netlify CLI becomes:

```text id="u0dffj"
node_modules/.bin/netlify
```

This is why the instructor later runs it directly from `.bin`.

---

# Why local installs are preferred in pipelines

Advantages:

| Local install       | Global install        |
| ------------------- | --------------------- |
| reproducible        | environment-dependent |
| project-scoped      | system-scoped         |
| safer               | permission issues     |
| version-controlled  | harder to manage      |
| works in containers | often problematic     |

This is standard modern CI/CD practice.

---

# Important DevOps principle here

CI/CD environments should be:

## Ephemeral and reproducible

Meaning:

* pipeline creates environment
* installs dependencies
* runs tasks
* environment can be destroyed afterward

No reliance on manually preinstalled tools.

# 1. Fetching website content using `curl`

Basic command:

```bash id="7gm8v5"
curl https://example.com
```

Purpose:

* sends HTTP request
* retrieves response body
* prints HTML source to terminal

Important concept:

```text id="jlwm0u"
curl retrieves raw page source, not rendered browser UI
```

This is critical.

---

# Raw HTML vs rendered browser content

Modern frontend frameworks:

* React
* Angular
* Vue
* Next.js

often render content dynamically using JavaScript.

`curl` only sees:

```text id="jlwm0x"
initial server response
```

NOT:

```text id="jlwm4b"
post-JavaScript rendered DOM
```

Meaning:

* some visible browser text may not appear in curl output

---

# Browser behavior

Browser does:

1. download HTML
2. download JS
3. execute JS
4. modify DOM
5. render UI

`curl` only performs:

```text id="jlwm7s"
step 1
```

# 2. Importance of HTTPS vs HTTP

Example mistake:

```bash id="jlwm5n"
curl http://example.com
```

instead of:

```bash id="0jlwmm"
curl https://example.com
```

Potential consequences:

* redirect responses
* different content
* errors
* security restrictions
* unexpected HTML

Important CI/CD lesson:

```text id="xjlwmg"
always verify actual response before asserting content
```

Do not assume endpoint correctness.

# 3. Searching website content using `grep`

Command:

```bash id="0jlwmx"
curl https://example.com | grep Valentino
```

Purpose:

* fetch content
* pipe into text search tool

Pipe operator:

```bash id="jlwmj8"
|
```

Meaning:

```text id="0jlwmq"
stdout of left command becomes stdin of right command
```

One of the most important Linux concepts.

---

# `grep` behavior

If match exists:

* matching line printed
* exit code = 0

If match missing:

* no output
* exit code = 1

---

# 4. Exit status codes

Using:

```bash id="jjlwmq"
echo $?
```

Purpose:

* inspect previous command exit code

Very important Linux behavior:

| Exit code | Meaning |
| --------- | ------- |
| 0         | success |
| non-zero  | failure |

---

# Why this matters in CI/CD

CI/CD systems:

* Jenkins
* GitHub Actions
* GitLab CI

automatically fail jobs when commands return:

```text id="0jlwm5"
non-zero exit codes
```

So:

```bash id="1jlwmf"
curl ... | grep Valentino
```

can function as:

```text id="8jlwm7"
deployment validation
```

without additional scripting.

# 5. Silent mode in curl

Using:

```bash id="xjlwm6"
curl -s https://example.com
```

Flag:

```text id="0jlwmc"
-s = silent
```

Suppresses:

* progress meter
* transfer statistics
* noisy output

Useful in:

* CI logs
* automation scripts
* cron jobs

---

# Important troubleshooting warning

Silent mode can hide useful errors.

Example:

```bash id="9jlwm5"
curl -s https://wrong-domain.com
```

May produce:

```text id="xjlwm7"
no visible error output
```

This makes debugging harder.

Operational recommendation:

```text id="0jlwmw"
remove silent flags during troubleshooting
```

Very important real-world debugging habit.

---

# 6. Quiet mode in grep

Using:

```bash id="0jlwm4"
grep -q Valentino
```

Flag:

```text id="jlwm3s"
-q = quiet
```

Behavior:

* suppress matching output
* rely only on exit code

Now command becomes:

```bash id="7jlwmu"
curl -s https://example.com | grep -q Valentino
```

No output appears.

Only exit code matters.

---

# 7. Fully silent validation commands

Example:

```bash id="9jlwmk"
curl -s https://example.com | grep -q Valentino
echo $?
```

Outputs:

```text id="4jlwm6"
0
```

Meaning:

```text id="0jlwmn"
text found successfully
```

If missing:

```text id="4jlwm2"
1
```

Meaning:

```text id="9jlwm0"
validation failed
```

# Important debugging principle

The transcript mentions:

```text id="6jlwmr"
decompose complex commands into smaller steps
```

This is a critical Linux/DevOps troubleshooting skill.

Instead of debugging:

```bash id="2jlwm3"
curl -s ... | grep -q ...
```

Break into:

1. curl only
2. inspect output
3. add grep
4. inspect exit codes

This isolates:

* network issues
* DNS failures
* TLS issues
* redirect problems
* grep mismatches

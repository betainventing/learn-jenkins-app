This lab explains fundamental Linux environment variable handling in a CI/CD context, especially how variables are created, accessed, interpolated, and used in shell scripts and build pipelines.

These concepts are foundational for:

* Jenkins pipelines
* GitHub Actions
* GitLab CI
* Docker builds
* Kubernetes manifests
* deployment automation

---

# 1. Checking if an environment variable exists

Variable:

```bash id="4l95iu"
VERSION
```

Checking its value:

```bash id="ncz5gf"
echo $VERSION
```

Behavior:

* if defined → prints value
* if undefined → prints empty output

Example:

```bash id="pjlwm8"
echo $VERSION
```

Output:

```text id="jlwmn3"
```

Meaning:

```text id="1eq0mc"
variable is undefined or empty
```

Important distinction:

* shell usually does NOT throw error for missing variables
* undefined variables silently expand to empty strings

This can cause dangerous CI/CD issues.

Example:

```bash id="jlwmk5"
docker push myapp:$VERSION
```

If VERSION undefined:

```bash id="jlwm57"
docker push myapp:
```

which may fail or behave unexpectedly.

# 3. Defining an environment variable

Using:

```bash id="jlwm1m"
export VERSION=1.2.3
```

Important syntax rule:

```bash id="jlwmn9"
NO spaces around =
```

Correct:

```bash id="jlwm6o"
VERSION=1.2.3
```

Wrong:

```bash id="jlwmvg"
VERSION = 1.2.3
```

Shell interprets the wrong form differently and fails.

---

# Why `export` matters

Difference:

Without export:

```bash id="jlwm7r"
VERSION=1.2.3
```

Variable exists only:

```text id="jlwmn5"
inside current shell
```

With export:

```bash id="jlwmnd"
export VERSION=1.2.3
```

Variable becomes inherited by:

* child processes
* scripts
* commands
* build tools

This is extremely important in CI/CD.

Example:

```bash id="jlwmho"
export REACT_APP_VERSION=1.0.50
npm run build
```

React build process can now access variable.

# Important quote behavior

## Double quotes

```bash id="jlwmzz"
echo "Version $VERSION"
```

Variable expands.

---

## Single quotes

```bash id="0jlwm1"
echo 'Version $VERSION'
```

Output:

```text id="xjlwm0"
Version $VERSION
```

No expansion occurs.

This is one of the most important shell scripting rules.

---

# Why this matters in CI/CD

Wrong quotes can silently break:

* Docker tags
* artifact names
* deployment versions
* URLs
* credentials injection

Example mistake:

```bash id="jlwm4q"
docker build -t 'app:$VERSION' .
```

Literally creates:

```text id="jlwmjq"
app:$VERSION
```

instead of:

```text id="jlwm0c"
app:1.2.3
```

# Redirection operator

Using:

```bash id="jlwmr1"
>
```

Example:

```bash id="jlwm5j"
echo "Build version $VERSION" > build/info.txt
```

Meaning:

* command stdout redirected into file
* file created if missing
* file overwritten if existing

---

# Problem encountered

Error:

```text id="jlwm2u"
No such file or directory
```

Reason:

```text id="jlwm90"
parent directory does not exist
```

Linux does NOT automatically create parent directories.

# Important operational lesson

The lab indirectly demonstrates a major CI/CD principle:

```text id="jlwmm5"
builds should produce traceable artifacts
```

Meaning:

* every artifact should identify:

  * version
  * build number
  * commit
  * timestamp
  * environment

This enables:

* debugging
* rollback verification
* deployment auditing
* production diagnosis

Without this:
you often cannot prove what is actually running which becomes a serious operational problem in production systems.

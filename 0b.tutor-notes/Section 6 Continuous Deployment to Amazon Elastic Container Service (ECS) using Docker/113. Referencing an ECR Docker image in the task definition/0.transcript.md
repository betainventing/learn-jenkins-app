# Deploying the Custom Application Image to ECS

At this point the pipeline can:

* Build Docker images
* Tag them
* Push them to Amazon Elastic Container Registry

Now the final step is:

* Deploy that custom image through Amazon Elastic Container Service.



---

# The ECR Image URI

Inside ECR, selecting the image tag reveals the full image URI.

Example structure:

```text id="’wini207"
<registry>/<repository>:<tag>
```

This fully qualified image reference tells ECS:

* Which image to pull
* From which registry
* Which exact version to deploy

---

# Updating the ECS Task Definition

The ECS task definition still referenced:

```text id="’wini208"
nginx
```

Now it must reference:

* The custom ECR image instead

---

# Important ECS Behavior

ECS itself does NOT store container images.

Instead:

1. ECS reads task definition
2. ECS pulls image from registry
3. ECS starts container from that image

---

# Creating a New Task Definition Revision

Inside ECS:

* Open task definition
* Create new revision

The key field updated:

```text id="’wini209"
Image URI
```

The ECR image URI is pasted there.



---

# Why the Full URI Matters

The URI contains:

* AWS account registry
* Repository name
* Image version tag

This uniquely identifies:

* Exact deployment artifact

---

# New Problem — ECS Permission Error

ECS initially throws an error related to:

* Task execution role

This introduces another major AWS concept:

* IAM execution roles for services

---

# Task Execution Role

ECS tasks require permissions to:

* Pull images from ECR
* Send logs
* Access AWS services

Without permissions:

* ECS cannot retrieve the private image

---

# Why ECS Needs Permissions

The image is private inside ECR.

So ECS must authenticate against ECR before:

* Pulling the container image

---

# Creating the Execution Role

AWS UI creates:

* New execution role automatically

This role grants ECS:

* Permission to pull private images



---

# Important Architectural Distinction

Two separate permission systems now exist:

| Permission Type         | Used By                |
| ----------------------- | ---------------------- |
| Jenkins IAM User        | Push images & deploy   |
| ECS Task Execution Role | Pull images at runtime |

This distinction is extremely important.

---

# New Task Definition Revision

After saving:

* ECS creates revision 13

The revision now references:

* Custom application image

instead of:

* Public Nginx image

---

# Updating the ECS Service

Next step:

* Update ECS service
* Select latest revision

This triggers:

* Deployment of custom application container

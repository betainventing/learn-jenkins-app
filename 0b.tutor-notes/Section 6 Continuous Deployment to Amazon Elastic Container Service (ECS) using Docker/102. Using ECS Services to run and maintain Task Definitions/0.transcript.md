# ECS Deployment Flow — From Task Definition to Running Container

At this stage:

* ECS cluster exists
* Task definition exists

But nothing is actually running yet. 

---

# Important ECS Concept

A task definition alone does NOT execute anything.

Conceptually:

```text id="3czd3m"
Task Definition = Blueprint
NOT
Running Application
```

This is one of the most important ECS concepts.

---

# Current State Before Deployment

Inside the ECS dashboard:

| Component       | Status |
| --------------- | ------ |
| Cluster         | Exists |
| Task Definition | Exists |
| Running Tasks   | 0      |
| Services        | None   |



---

# Missing Component — ECS Service

The lecture introduces the final major component:

* ECS Service

---

# What Is an ECS Service?

An ECS service is responsible for:

* Running tasks
* Maintaining desired number of tasks
* Restarting failed containers
* Managing deployments

Conceptually:

```text id="vjlwm3"
Service = Task Lifecycle Manager
```

Without a service:

* Containers are not continuously managed.

---

# ECS Architecture So Far

The architecture now becomes:

```text id="9w0mxl"
Cluster
   ↓
Task Definition
   ↓
Service
   ↓
Running Tasks
```

---

# Creating the Service

Inside the cluster:

* Open `Services`
* Click `Create`

The service connects:

* Cluster
  → with
* Task Definition



---

# Capacity Provider

Selected provider:

* AWS Fargate

Meaning:

* AWS-managed serverless container execution

No EC2 infrastructure management required.

---

# Deployment Type

The deployment type remains:

* Service

Why service mode matters:

* ECS continuously ensures tasks remain running.

If a container crashes:

* ECS automatically recreates it.

---

# Task Definition Selection

Selected:

* Latest revision of task definition family

This enables rolling forward through newer versions later.

---

# Service Naming Convention

Example:

```text id="k5xw91"

```

* Application naming

---

# Desired Tasks

Configured value:

```text id="jlwm0m"
1
```

Meaning:

* ECS should always keep exactly one running task.

---

# Desired State Model

This introduces an important orchestration principle.

You declare:

```text id="yzg4m8"
Desired State = 1 Running Container
```

ECS continuously works to maintain that state.

If:

* Container crashes
* Infrastructure fails

ECS attempts recovery automatically.

This is declarative orchestration behavior.

Eventually ECS reports:

# ECS Task Reality

The running task is:

* A live Docker container instance

In this example:

* Nginx web server container

running inside AWS-managed infrastructure.

---

# Accessing the Container

Inside the running task details:

* Networking tab shows public IP

This public IP belongs to:

* The running Fargate task/network interface

---

# Initial Connectivity Failure

Opening the public IP initially fails.

Why?

Because:

* Network traffic is blocked.

This introduces another critical AWS concept:

* Security Groups

---

# Security Groups

A security group is effectively:

* A virtual firewall

Managed by AWS.

Controls:

* Inbound traffic
* Outbound traffic

for cloud resources.

---

# Inbound Rules

Initially:

* Public HTTP traffic not allowed

Result:

* Browser timeout
* No web server response

Even though:

* Nginx container is running correctly



---

# Fixing Connectivity

An inbound rule is added:

| Setting | Value         |
| ------- | ------------- |
| Type    | HTTP          |
| Port    | 80            |
| Source  | IPv4 Anywhere |

This allows:

* Public internet traffic
  → to reach
* Port 80 on the container

---

# Why Port 80?

Nginx listens on:

* TCP port 80

Earlier task definition port mapping exposed:

* Container port 80

Now the security group permits access to it.

---

# Security Flow

Complete networking path now becomes:

```text id="jlwm9k"
Internet User
   ↓
Security Group Allows HTTP
   ↓
Public IP
   ↓
Fargate Task
   ↓
Port Mapping
   ↓
Nginx Container
```

---

# Important Security Observation

Before the security group rule:

* Container was healthy
* Application was running
* Networking still failed

This is extremely common in AWS troubleshooting.

---

# Final Result

Opening the public IP now shows:

```text id="jlwm7t"
Welcome to nginx!
```

Meaning:

* ECS deployment succeeded
* Fargate networking functional
* Security rules configured correctly
* Container accessible from internet

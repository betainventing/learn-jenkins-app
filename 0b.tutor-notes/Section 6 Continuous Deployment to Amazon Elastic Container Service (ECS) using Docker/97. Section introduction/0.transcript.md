# Section Overview — Docker + AWS Deployment

This section moves from:

* Static website hosting on Amazon S3

to:

* Containerized application deployment using Docker and AWS container services.

This is much closer to how modern production systems are deployed.

---

# Previous Deployment Model

Earlier workflow:

```text id="2n9hmt"
Static Files → S3 Bucket → Website Hosting
```

Characteristics:

* Simple
* Cheap
* Serverless
* Good for static frontend sites

Limitations:

* No backend runtime
* No process management
* No container orchestration
* No application isolation

---

# Why Docker Changes Everything

Modern applications usually require:

* Runtime environments
* Dependencies
* Libraries
* Services
* Specific OS tooling

Running applications directly on servers creates problems:

* Environment inconsistencies
* Dependency conflicts
* “Works on my machine” issues

Docker solves this through containerization.

---

# What Does “Dockerize” Mean?

Dockerizing an application means:

```text id="9g4wy7"
Application + Dependencies + Runtime + Configuration
→ Container Image
```

The application becomes portable and reproducible.

---

# Container Concept

A Docker container is:

* Isolated runtime environment
* Lightweight compared to full VMs
* Packaged application execution unit

Container includes:

* Application code
* Runtime
* System libraries
* Dependencies
* Configuration

This ensures consistent behavior across:

* Developer machines
* CI/CD pipelines
* Testing environments
* Production servers

---

# Docker Image

A Docker image is:

* Immutable blueprint/template
* Used to create containers

Usually built from a:

* `Dockerfile`

The image contains:

* Base OS layer
* Installed packages
* Application files
* Startup commands

# AWS Services Introduced

## 1. Amazon ECR

Amazon Elastic Container Registry

Purpose:

* Store Docker images

Equivalent concept:

* Docker Hub
* Private container registry

ECR stores:

* Versioned container images
* Private repositories
* Deployment artifacts

---

# 2. Amazon ECS

Amazon Elastic Container Service

Purpose:

* Run and manage Docker containers

ECS handles:

* Container scheduling
* Scaling
* Deployment
* Task execution
* Service management

This removes the need to manually manage Docker containers on raw EC2 servers.

---

# Conceptual Difference

| Service | Purpose               |
| ------- | --------------------- |
| ECR     | Store Docker images   |
| ECS     | Run Docker containers |

# Why Difficulty Increases

Container deployments involve:

* Image lifecycle management
* Registry authentication
* Runtime orchestration
* Networking
* Permissions
* Environment variables
* Service discovery
* Port mapping

This is a major jump from static file hosting.

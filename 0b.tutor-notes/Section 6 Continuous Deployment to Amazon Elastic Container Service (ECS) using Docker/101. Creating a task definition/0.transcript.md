# ECS Task Definition — The Deployment Blueprint

The ECS cluster currently exists but does nothing because no instructions were provided to it.

To tell Amazon Elastic Container Service what to run, a **task definition** must be created. 

---

# What Is a Task Definition?

A task definition is a JSON-based configuration blueprint describing:

* Which container image to run
* CPU allocation
* Memory allocation
* Networking
* Ports
* Protocols
* Runtime behavior

Conceptually:

```text id="1bd5k2"
Task Definition = Deployment Instructions for ECS
```



---

# Why JSON Instead of AWS UI?

AWS provides:

* Visual form-based configuration
  OR
* Raw JSON configuration

The lecture intentionally uses JSON because:

* Easier to automate
* Better for CI/CD
* Version controllable
* Infrastructure-as-code friendly

This becomes extremely important later for Jenkins automation.

# Port Mapping

The lecture introduces an extremely important container concept:

* Port mapping

---

# Why Port Mapping Exists

Containers run in isolated networking namespaces.

Without mapping:

* External traffic cannot reach the container application

Port mapping exposes container ports.

---

# ECS Port Mapping Configuration

Example configuration:

```json id="njlwm0"
"portMappings": [
  {
    "name": "nginx-80-tcp",
    "containerPort": 80,
    "hostPort": 80,
    "protocol": "tcp",
    "appProtocol": "http"
  }
]
```



---

# Meaning of Each Field

| Field           | Purpose                    |
| --------------- | -------------------------- |
| `containerPort` | Port inside container      |
| `hostPort`      | Port exposed externally    |
| `protocol`      | Transport protocol         |
| `appProtocol`   | Application-layer protocol |

---

# Port 80

Port:

```text id="jlwm6g"
80
```

is standard HTTP traffic.

Nginx listens internally on:

* Port 80

The mapping allows internet traffic to reach the web server.

# Why Resource Configuration Matters

Fargate pricing depends directly on:

* CPU allocated
* Memory allocated
* Runtime duration

Higher allocations:

* Increase costs

Even idle containers consume allocated resources.

---

# Important AWS Validation Rule

Fargate only supports certain valid CPU/memory combinations.

Example:

* `256 CPU` supports `512 MB memory`

Invalid combinations are rejected.

This is why AWS initially returned:

* Memory validation error

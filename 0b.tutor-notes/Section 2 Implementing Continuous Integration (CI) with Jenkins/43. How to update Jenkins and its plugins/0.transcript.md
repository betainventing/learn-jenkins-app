Install Jenkins using Docker Compose
This repository contains a Docker Compose configuration for a quick installation of Jenkins. This setup is not intended for production systems.

Credits: This approach is mostly based on the official instructions but takes advantage of Docker Compose (by using a docker-compose.yml file) to reduce the number of steps needed to get Jenkins up and running.

Docker Installation
Step 0
Install Docker locally (probably using Docker Desktop is the easiest approach).

Step 1
Clone this repository or download its contents.

Step 2
Open a terminal window in the same directory where the Dockerfile from this repository is located. Build the Jenkins Docker image:

docker build -t my-jenkins .
Step 3
Start Jenkins:

docker compose up -d
Step 4
Open Jenkins by going to: http://localhost:8080/ and finish the installation process.

Step 5
If you wish to stop Jenkins and get back to it later, run:

docker compose down
If you wish to start Jenkins again later, just run the same command from Step 3.

Removing Jenkins
Once you are done playing with Jenkins, maybe it is time to clean things up.

Run the following command to terminate Jenkins and to remove all volumes and images used:

docker compose down --volumes --rmi all

### Jenkins Updates & Warnings — What You Should Actually Do

---

## 1. What Those Warnings Mean

When you see:

* Security warnings
* Plugin vulnerabilities
* New version available

It means:

```text id="vbt0g4"
Your Jenkins instance is outdated or has known vulnerabilities
```

These apply to:

* Jenkins **core**
* Installed **plugins** 

---

## 2. Critical Rule (Production vs Learning)

### Local / Learning Setup

* Safe to update directly
* Low risk

### Production Setup

Do NOT blindly update

Follow process:

```text id="g7k5f8"
Plan → Document → Update → Test → Repeat
```

---

## 3. Step 1 — Document Before Updating

Track:

| Field       | Example         |
| ----------- | --------------- |
| Date        | 2026-04-24      |
| Component   | Jenkins Core    |
| Reason      | Security update |
| Old Version | 2.x.x           |
| New Version | 2.y.y           |
| Status      | Success         |

Why:

```text id="pjijxk"
If something breaks → you know what changed
```

---

## 4. Updating Jenkins (Docker-Based Setup)

### Step 1: Stop Jenkins

```bash id="6qg2m5"
docker compose down
```

---

### Step 2: Rebuild Image

```bash id="cbq8q9"
docker compose build
```

* Pulls latest Jenkins base image

---

### Step 3: Start Jenkins

```bash id="l9d2vn"
docker compose up -d
```

---

### Step 4: Verify Version

* Open Jenkins
* Scroll bottom → check version

---

## 5. Updating Plugins

### Step 1: Go to Plugin Manager

```text id="s2d1xv"
Manage Jenkins → Plugins → Updates
```

---

### Step 2: Select Plugin

Example:

```text id="7y33gr"
GitHub Plugin
```

---

### Step 3: Update

* Click **Update**
* Restart Jenkins

---

## 6. Restart Methods

### UI Option

```text id="7du3ec"
Restart Jenkins when installation completes
```

---

### Direct URL

```bash id="h99l4d"
http://localhost:8080/restart
```

---

## 7. After Update — Verify

Check:

* No warnings
* Plugin version updated
* Pipelines still working

---

## 8. Golden Rule for Plugins

```text id="dy85h3"
Update ONE plugin at a time
```

Why:

* Easier troubleshooting
* Isolate failures

---

## 9. What Can Go Wrong

If you update everything at once:

```text id="9ru9jt"
Something breaks → you don’t know why
```

---

## 10. Recommended Strategy

```text id="g3a8gi"
Day 1 → Update 1 plugin  
Day 2 → Observe  
Day 3 → Update next  
```

---

## 11. Why Updates Matter

Without updates:

* Security vulnerabilities
* Compatibility issues
* Plugin failures

With updates:

```text id="4dw1cu"
Stable + Secure + Supported Jenkins
```

---

## 12. Real DevOps Practice

In production:

* Maintenance window required
* Team communication needed
* Backup recommended

---

## 13. Key Insight

Updating Jenkins is NOT just:

```text id="z6t67x"
Click update → done
```

It is:

```text id="zzv9d4"
Controlled change management process
```

---

## 14. Final Mental Model

```text id="mrq3vh"
Jenkins = Core + Plugins
Updates = Risk + Security Fix
Your job = Control the risk
```

---

## 15. Practical Takeaway

* Always document updates
* Update incrementally
* Test after each change
* Prioritize security fixes

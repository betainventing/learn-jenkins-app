## What Problem Jenkins Solves

The example describes a common software development problem:

A developer named Priya repeatedly performs manual tasks after every code change:

* Rebuilding the application
* Testing it
* Uploading it to a server
* Making it available to customers

These tasks are:

* Repetitive
* Time-consuming
* Error-prone

Because humans perform the same tasks repeatedly, mistakes happen:

* Deployments fail
* Applications go offline
* Bugs reach users
* Processes become inconsistent

This is exactly the type of problem Jenkins is designed to solve.

---

# What Jenkins Is

Jenkins is:

* Free
* Open source
* An automation server

Its primary purpose is to automate software development tasks.

Typical automated tasks include:

* Building applications
* Running tests
* Packaging software
* Deploying applications

---

# Simplified Explanation

Jenkins acts like a robot assistant for developers.

Instead of developers manually performing repetitive operations, Jenkins automatically performs them whenever code changes occur.

Example workflow:

1. Developer writes code
2. Jenkins detects the change
3. Jenkins builds the application
4. Jenkins runs automated tests
5. Jenkins creates deployable artifacts
6. Jenkins deploys the application to servers

This reduces manual intervention significantly.

---

# Benefits of Jenkins

Using Jenkins provides several advantages.

## 1. Automation

Manual repetitive work becomes automated.

Developers focus more on writing code instead of operational tasks.

---

## 2. Consistency

Every build and deployment follows the same process.

This reduces human error.

---

## 3. Faster Feedback

If code breaks something:

* Tests fail immediately
* Developers are notified quickly
* Problems are fixed earlier

---

## 4. Improved Reliability

Automated deployments are generally more reliable than manual deployments.

Applications experience less downtime caused by deployment mistakes.

---

## 5. Better Productivity

Developers spend less time on repetitive operations and more time building features.

# CI/CD Concepts Mentioned

The lecture introduces:

* Continuous Integration (CI)
* Continuous Deployment / Continuous Delivery (CD)

These are core DevOps practices.

## Continuous Integration (CI)

CI means developers frequently integrate code changes into a shared repository.

Automated systems then:

* Build the code
* Run tests
* Verify that the application still works

Goal:
Detect issues early.

---

## Continuous Deployment / Delivery (CD)

CD automates the release process after successful testing.

This may include:

* Packaging applications
* Deploying to staging
* Deploying to production servers

Goal:
Release software faster and more reliably.

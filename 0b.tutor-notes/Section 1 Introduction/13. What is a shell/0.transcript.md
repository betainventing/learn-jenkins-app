This section is explaining one of the most fundamental realities of DevOps and automation:

> Jenkins does not “click buttons.”
> Jenkins executes commands.

That is why Linux command-line knowledge is essential for DevOps engineers.

---

# CLI vs GUI

## GUI (Graphical User Interface)

A GUI is visual interaction:

* clicking
* dragging
* opening windows
* pressing buttons

Example:

Creating a folder manually:

1. Right click
2. New Folder
3. Open editor
4. Create file

This is GUI-driven interaction.

---

## CLI (Command Line Interface)

A CLI uses text commands instead.

Example:

```bash id="y9b8ee"
mkdir build
touch build/computer.txt
echo "keyboard" >> build/computer.txt
```

This performs the same work without graphical interaction.

---

# Why DevOps Uses CLI

Automation systems like Jenkins operate on servers.

Most production servers:

* do not have graphical desktops
* do not have monitors
* do not have mouse/keyboard interaction
* are remote systems

So automation relies entirely on command execution.

That is why Jenkins pipelines heavily use:

```groovy id="g3apc0"
sh 'linux-command'
```

---

# What the `sh` Step Means

In Jenkins pipelines:

```groovy id="e7d4iy"
sh 'mkdir build'
```

means:

> Run this command inside a Linux shell.

`sh` = shell execution.

---

# What Is a Shell?

A shell is the command interpreter between the user and the operating system.

It:

1. receives commands
2. interprets them
3. asks the operating system to execute them

Common Linux shells:

| Shell  | Description                |
| ------ | -------------------------- |
| `sh`   | basic POSIX shell          |
| `bash` | Bourne Again Shell         |
| `zsh`  | advanced interactive shell |
| `fish` | user-friendly shell        |

In CI/CD, `bash` and `sh` are most common.

---

# Important Terminology

These terms are often used interchangeably:

| Term     | Meaning                        |
| -------- | ------------------------------ |
| CLI      | Command Line Interface         |
| Terminal | Application used to access CLI |
| Console  | Text-based system interface    |
| Shell    | Command interpreter            |

Technically different, but in practice people mix them constantly.

# Why Command Order Matters

Pipelines are sequential automation.

Example:

```bash id="ijjlwm"
mkdir build
touch build/computer.txt
```

works.

But reversing them:

```bash id="fz4ehg"
touch build/computer.txt
mkdir build
```

fails because:

```text id="j2p6rj"
build/
```

does not exist yet.

This is one of the most important concepts in automation:

> Every command depends on system state created by previous commands.

---

# Jenkins Pipelines Are Just Automated Shell Scripts

This is a critical mental model.

A Jenkins pipeline is basically:

* orchestration
* sequencing
* conditional execution
* shell command automation

Example:

```groovy id="vv7k9o"
pipeline {
    agent any

    stages {
        stage('Build') {
            steps {
                sh 'npm ci'
                sh 'npm test'
                sh 'docker build -t app .'
            }
        }
    }
}
```

Jenkins itself is not building software.

It is coordinating commands.

# Real DevOps Example

Typical CI/CD step:

```groovy id="cf0z95"
steps {
    sh 'npm ci'
    sh 'npm run build'
    sh 'docker build -t app .'
    sh 'docker push repo/app:latest'
}
```

Every line is just a Linux command executed in sequence.

---

# Why GUI Automation Is Avoided

Automating GUIs is:

* fragile
* slow
* inconsistent
* difficult to reproduce

Example problems:

* window positions change
* screen resolution changes
* dialogs appear
* timing issues happen

CLI automation is:

* deterministic
* scriptable
* reproducible
* fast
* server-friendly

That is why DevOps relies heavily on shells and scripts.

## Jenkins + DevOps Recap

### 1. Jenkins Job Types

Jenkins mainly provides two common job styles:

#### Freestyle Jobs

* Traditional Jenkins job configuration through the GUI.
* Simple and beginner-friendly.
* Configuration stored manually inside Jenkins.
* Harder to version-control and scale.

#### Pipeline Jobs

* Modern Jenkins standard.
* Defined as code using a `Jenkinsfile`.
* Supports CI/CD best practices.
* Easier to maintain, review, reuse, and version-control with Git.
* Preferred in modern DevOps environments.

## 2. Linux Commands Used in Pipelines

### `echo`

Used to print messages or variable values.

```bash
echo "Build started"
echo $HOME
```

Common uses:

* Debugging
* Logging
* Viewing environment variables

---

### `mkdir`

Creates directories.

```bash
mkdir project
mkdir -p app/logs
```

`-p` creates parent directories if needed.

---

### `touch`

Creates a file if it does not exist or updates its timestamp.

```bash
touch file.txt
```

Important behavior:

* Does not erase existing contents.
* Only updates modification time if file already exists.

---

### `rm`

Removes files or directories.

```bash
rm file.txt
rm -rf folder/
```

Options:

* `-r` → recursive
* `-f` → force removal

Used frequently for cleanup operations in pipelines.

---

### `sleep`

Pauses execution.

```bash
sleep 5
```

Useful for:

* Simulating long-running tasks
* Waiting for services to initialize

---

### `cat`

Displays file contents.

```bash
cat file.txt
```

Useful for:

* Viewing generated artifacts
* Debugging pipeline output

---

### `test`

Checks conditions like file existence.

```bash
test -f app.txt
```

Common checks:

* File exists
* Directory exists
* Variable comparisons

Very important because Jenkins relies on command success/failure.

---

### `grep`

Searches for text patterns inside files.

```bash
grep "ERROR" logs.txt
```

Used heavily in automation for:

* Log inspection
* Validation
* Searching configuration values

---

# 3. Jenkins Logs

Jenkins console output is one of the most important debugging tools.

Logs help identify:

* Failed commands
* Incorrect paths
* Missing files
* Permission issues
* Syntax errors
* Environment variable problems

Pipeline troubleshooting usually starts with reading console logs carefully.

---

# 4. Exit Codes

Linux commands return exit codes after execution.

### Success

```text
0
```

### Failure

```text
non-zero
```

Examples:

* `1`
* `2`
* `127`

Jenkins uses these exit codes to decide whether:

* A stage succeeds
* A stage fails
* The pipeline should stop

Example:

```bash
grep "hello" file.txt
```

If the string is found:

* exit code = `0`

If not found:

* exit code ≠ `0`
* Jenkins marks the step as failed.

# 5. DevOps Philosophy

DevOps is not:

* A programming language
* A single tool
* Jenkins
* Docker
* Kubernetes

DevOps is primarily:

* A culture
* A workflow philosophy
* A collaboration model

Goals include:

* Faster software delivery
* Automation
* Reliability
* Continuous improvement
* Better collaboration between development and operations teams

Tools only support these practices.

# 7. Overall Understanding

At this stage, the foundational workflow is becoming clear:

1. Jenkins executes shell commands.
2. Linux commands perform automation tasks.
3. Jenkins monitors command exit codes.
4. Logs provide execution visibility.
5. Pipelines automate repeatable software delivery processes.
6. DevOps focuses on improving the entire delivery lifecycle through automation and collaboration.

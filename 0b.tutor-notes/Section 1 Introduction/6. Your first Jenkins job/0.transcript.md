# Creating Your First Jenkins Job

In Jenkins, a **job** is an automated task consisting of commands or steps Jenkins executes.

Examples:

* Running shell commands
* Building applications
* Running tests
* Deploying applications
* Executing scripts
* Automating DevOps workflows

---

# Two Main Job Types Introduced

| Job Type          | Configuration Style |
| ----------------- | ------------------- |
| Freestyle Project | GUI-based           |
| Pipeline          | Code-based          |

The lecture demonstrates both.

---

# What Is a Freestyle Project?

A freestyle project is:

* Configured mostly through Jenkins UI
* Checkbox/menu driven
* Older Jenkins approach
* Easier for beginners
* Harder to maintain for complex automation

Configuration is stored internally by Jenkins rather than version-controlled code.

```text

```


# Step 3 — Add Shell Command

Example:

```bash

```

---

# Understanding `echo`

`echo` is a Linux shell command.

Purpose:

* Prints text to terminal/console
* Displays variables
* Useful for debugging scripts

Example:

```bash
echo "Hello"
```

Output:

```text
Hello
```

---

# Understanding Strings

This part:

```bash
"Hello from Jenkins"
```

is called a string.

It is passed as an argument to the `echo` command.

---

# Major Difference Between Freestyle and Pipeline

## Freestyle

Configuration stored mainly in UI.

## Pipeline

Configuration stored as code.

This is the critical concept.

---

# Pipeline as Code

Pipelines use a scripting language.

Advantages:

| Advantage       | Explanation              |
| --------------- | ------------------------ |
| Version control | Store in Git             |
| Reproducibility | Same pipeline everywhere |
| Auditing        | Track changes            |
| Scalability     | Easier for large CI/CD   |
| Automation      | Fully programmable       |

This concept is called:

```text
Pipeline as Code
```

---

# Basic Pipeline Structure

Example:

```groovy
pipeline {
    agent any

    stages {
        stage('Hello') {
            steps {
                echo 'Hello World'
            }
        }
    }
}
```

---

# Understanding Pipeline Components

## `pipeline`

Defines entire Jenkins pipeline.

---

## `agent any`

Means:

```text
Run on any available Jenkins agent/node
```

---

## `stages`

Container holding multiple stages.

---

## `stage`

Logical phase of pipeline.

Examples:

* Build
* Test
* Deploy
* Security Scan

---

## `steps`

Commands executed inside a stage.

---

# Curly Braces `{}`

Pipeline syntax is based on Groovy DSL.

Curly braces define blocks:

```groovy
stage('Build') {
    steps {
    }
}
```

# Jenkins `echo` vs Shell `echo`

This lecture highlights an important distinction.

---

# Jenkins Pipeline `echo`

Example:

```groovy
echo 'Hello'
```

This is:

* Jenkins pipeline step
* NOT Linux shell command

Executed by Jenkins itself.

---

# Shell Command Execution

To run Linux commands inside pipeline:

```groovy
sh 'echo Hello'
```

`sh` means:

```text
Execute shell command
```

This launches a shell inside Jenkins environment.

---

# Example

```groovy
pipeline {
    agent any

    stages {
        stage('Hello') {
            steps {
                sh 'echo Hello from Jenkins'
            }
        }
    }
}
```

---

# Why `sh` Is Important

Most DevOps work in Jenkins uses shell commands.

Examples:

```bash
docker build
kubectl apply
terraform plan
npm install
mvn package
ansible-playbook
```

All usually executed through:

```groovy
sh 'command'
```

---

# Example — `whoami`

Pipeline:

```groovy
sh 'whoami'
```

---

# Understanding `whoami`

Linux command:

```bash
whoami
```

Purpose:

```text
Displays current logged-in user
```

Example output:

```text
jenkins
```

Meaning:

The shell command is executed as Jenkins OS user inside container/server.

# Pipeline Concept

A pipeline is essentially:

```text
A sequence of automated stages
```

Example real-world CI/CD pipeline:

```text
Code Checkout
    ↓
Install Dependencies
    ↓
Run Tests
    ↓
Build Application
    ↓
Build Docker Image
    ↓
Push Image
    ↓
Deploy
```

Each phase becomes a Jenkins stage.

---

# Typical Real Jenkins Pipeline

Example:

```groovy
pipeline {
    agent any

    stages {

        stage('Build') {
            steps {
                sh 'npm install'
            }
        }

        stage('Test') {
            steps {
                sh 'npm test'
            }
        }

        stage('Docker Build') {
            steps {
                sh 'docker build -t app .'
            }
        }

        stage('Deploy') {
            steps {
                sh 'kubectl apply -f deployment.yaml'
            }
        }
    }
}
```

# Freestyle vs Pipeline Comparison

| Feature           | Freestyle | Pipeline  |
| ----------------- | --------- | --------- |
| Configuration     | GUI       | Code      |
| Version Control   | Difficult | Easy      |
| Scalability       | Limited   | Excellent |
| Recommended Today | Mostly no | Yes       |
| CI/CD Support     | Basic     | Advanced  |
| Reproducibility   | Weak      | Strong    |

---

# Industry Reality

Modern DevOps and CI/CD almost always use:

```text
Pipeline jobs
```

Freestyle jobs still exist mainly for:

* Simple automation
* Legacy Jenkins setups
* Quick experiments

The critical transition in Jenkins learning is:

```text
GUI-based jobs → Pipeline as Code
```

That transition is foundational for:

* CI/CD
* GitOps

* Enterprise Jenkins usage

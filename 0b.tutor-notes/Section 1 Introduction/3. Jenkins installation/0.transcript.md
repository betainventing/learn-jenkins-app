# Jenkins Installation Using Docker Desktop

## Why Use Docker for Jenkins

There are multiple ways to install Jenkins, but using Docker ensures:

* Same environment as the course instructor
* Consistent behavior across systems
* Easier troubleshooting
* Quick setup and cleanup
* No need to manually install Jenkins dependencies

If Jenkins is installed directly on the host OS, configurations may differ and examples may fail.

---

# Overall Installation Flow

1. Install Docker Desktop
2. Verify Docker works
3. Download Jenkins Docker configuration from GitHub
4. Build Jenkins Docker image
5. Start Jenkins containers
6. Unlock and configure Jenkins
7. Create Jenkins user
8. Access Jenkins in browser

---

# Step 1 — Install Docker Desktop

Install Docker Desktop for:

* Windows
* macOS
* Linux

Recommended:

* Create a Docker account
* Enable virtualization in BIOS if Docker fails to start
* On Windows, WSL2 is usually required

Official websites:

* [Docker Desktop](https://www.docker.com/products/docker-desktop/?utm_source=chatgpt.com)
* [Docker Hub](https://hub.docker.com?utm_source=chatgpt.com)

---

# Step 2 — Verify Docker Installation

Run:

```bash
docker run hello-world
```

What happens:

1. Docker checks for the `hello-world` image locally
2. If missing, Docker downloads it
3. Docker creates and runs a container
4. Container prints:

```text
Hello from Docker!
```

If you see that message:

* Docker Engine works
* Image pulling works
* Containers work correctly

---

# Step 3 — Download Jenkins Docker Repository

Clone the repository:

```bash
git clone <repository-url>
```

Or download ZIP from GitHub.

Move into project directory:

```bash
cd install-jenkins-docker
```

This directory contains:

* `Dockerfile`
* `docker-compose.yml`
* Jenkins configuration

---

# Step 4 — Build Jenkins Docker Image

Run:

```bash
docker compose build
```

What this does:

* Reads Dockerfile
* Downloads base Jenkins image
* Installs additional tools/plugins
* Creates a custom Jenkins image locally

This only needs to be done once unless the Dockerfile changes.

---

# Step 5 — Start Jenkins Containers

Run:

```bash
docker compose up
```

Or detached mode:

```bash
docker compose up -d
```

What Docker Compose does:

* Reads `docker-compose.yml`
* Creates required containers
* Creates Docker networks
* Starts Jenkins container
* Maps ports between container and host

If everything is successful:

* Containers show status `running`
* No red error messages appear

---

# Step 6 — Open Jenkins

Open browser:

```text
http://localhost:8080
```

Explanation:

| Component | Meaning                          |
| --------- | -------------------------------- |
| localhost | Your own computer                |
| 8080      | Port mapped to Jenkins container |

Jenkins runs inside Docker but is accessible through host port 8080.

---

# Step 7 — Unlock Jenkins

When Jenkins starts first time, it requires an initial admin password.

Jenkins displays a path like:

```text
/var/jenkins_home/secrets/initialAdminPassword
```

---

# Method 1 — Get Password from Docker Desktop Logs

Inside Docker Desktop:

1. Open Jenkins container
2. Open Logs tab
3. Find:

```text
Please use the following password to proceed...
```

---

# Method 2 — Use Container Terminal

Inside Docker Desktop:

1. Open Jenkins container
2. Open Exec/Terminal

Run:

```bash
cat /var/jenkins_home/secrets/initialAdminPassword
```

Explanation:

| Command | Purpose              |
| ------- | -------------------- |
| cat     | Prints file contents |

Copy password and paste into Jenkins browser page.

---

# Step 8 — Install Suggested Plugins

Choose:

```text
Install suggested plugins
```

Jenkins plugins provide functionality such as:

* Git integration
* Pipelines
* Credentials management
* Docker support
* Build tools integration

Without plugins, Jenkins is mostly an empty platform.

---

# Step 9 — Create Jenkins User

Create:

* Username
* Password
* Email

Avoid using temporary admin password permanently.

Example:

| Field    | Example                                     |
| -------- | ------------------------------------------- |
| Username | admin                                       |
| Password | strong-password                             |
| Email    | [user@example.com](mailto:user@example.com) |

---

# Step 10 — Finish Setup

Jenkins URL:

```text
http://localhost:8080
```

Click:

```text
Save and Finish
```

Then:

```text
Start using Jenkins
```

You reach Jenkins dashboard.

# Understanding the Architecture

## What Is Running

Docker Compose usually creates:

| Component         | Purpose                 |
| ----------------- | ----------------------- |
| Jenkins container | Runs Jenkins            |
| Docker network    | Container communication |
| Volumes           | Persistent Jenkins data |

---

# Important Docker Commands

## Stop Jenkins

Inside project directory:

```bash
docker compose down
```

What happens:

* Stops containers
* Removes containers
* Keeps images and volumes unless explicitly removed

---

## Start Jenkins Again

```bash
docker compose up
```

Or detached:

```bash
docker compose up -d
```

Since images already exist locally, startup becomes much faster.

---

# Useful Docker Commands

## Show Running Containers


## Show All Containers


## Show Images


## View Logs


## Enter Running Container


# Important Concepts

## Docker Image

A blueprint/template used to create containers.

Example:

```text
jenkins/jenkins:lts
```

---

## Docker Container

A running instance of an image.

Image → Container relationship:

```text
Image = Template
Container = Running process
```

---

# Why Docker Compose Is Used

Without Docker Compose:

* Long docker commands
* Manual networking
* Manual volume configuration

With Docker Compose:

* Single configuration file
* One command startup
* Easier management

---

# Common Issues

## Port 8080 Already Used

Error:

```text
Bind for 0.0.0.0:8080 failed
```

Solution:

* Stop service using 8080
* Or change mapped port in `docker-compose.yml`

Example:

```yaml
ports:
  - "9090:8080"
```

Access Jenkins:

```text
http://localhost:9090
```

---

## Docker Desktop Not Starting

Possible causes:

* Virtualization disabled
* WSL2 missing
* Hyper-V conflicts
* Insufficient RAM

---

## Jenkins Keeps Restarting

Possible reasons:

* Low memory
* Corrupted volumes
* Plugin failures

Check:

```bash
docker logs <container-id>
```

---

# Recommended Minimum System Resources

| Resource | Recommended   |
| -------- | ------------- |
| RAM      | 8 GB          |
| CPU      | 4 cores       |
| Disk     | SSD preferred |

Docker + Jenkins + browsers can consume significant RAM.

# Production vs Local Setup

This setup is mainly for:

* Learning
* Development
* Testing

Production Jenkins usually includes:

* Reverse proxy (Nginx/Apache)
* HTTPS
* External authentication
* Backup strategy
* Persistent storage
* Dedicated agents/nodes
* Kubernetes or VM deployment

---

# Key Takeaways

* Jenkins is being run inside Docker containers
* Docker Compose manages the setup
* Jenkins data persists using Docker volumes
* `localhost:8080` maps host machine to Jenkins container
* Plugins extend Jenkins functionality
* Docker simplifies installation and consistency

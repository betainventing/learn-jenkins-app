This section explains a better way to organize shell commands inside a Jenkins Pipeline.

The instructor is optimizing the pipeline by reducing multiple repeated `sh` steps into a single multiline shell block.

---

# Problem with Multiple `sh` Steps

Initially the pipeline probably looked similar to this:

```groovy id="0qhj7i"
sh 'mkdir laptop'
sh 'touch laptop/mainboard'
sh 'touch laptop/display'
sh 'touch laptop/keyboard'
sh 'echo "Build completed"'
```

Every `sh` step:

1. Jenkins controller sends instruction to agent
2. Agent launches a shell
3. Command executes
4. Result is returned back to Jenkins

This happens repeatedly for every single `sh`.

---

# Why This Is Less Efficient

Each `sh` step introduces overhead:

* process creation
* shell initialization
* controller-agent communication
* logging setup
* command dispatching

For tiny examples this overhead is negligible.

But in large CI/CD pipelines with hundreds of commands:

* execution becomes slower
* logs become noisy
* pipelines become harder to maintain

---

# Better Approach: Multiline Shell Block

Instead of:

```groovy id="5l7rga"
sh 'command1'
sh 'command2'
sh 'command3'
```

you can use:

```groovy id="q4bhl5"
sh '''
command1
command2
command3
'''
```

This creates:

* one shell session
* one execution block
* cleaner logs
* lower overhead

---

# Triple Single Quotes

The syntax:

```groovy id="ktlkg8"
'''
'''
```

is Groovy multiline string syntax.

Inside Jenkins Pipeline:

```groovy id="e2g0ny"
sh '''
mkdir laptop
touch laptop/mainboard
touch laptop/display
touch laptop/keyboard
'''
```

all commands run sequentially inside one shell process.

# Important Internal Behavior

With separate `sh` calls:

```text id="s7vlmi"
Jenkins Controller
   ↓
Agent executes one command
   ↓
Returns result
   ↓
Next command
```

With multiline `sh`:

```text id="s5xq74"
Jenkins Controller
   ↓
Agent receives one shell script
   ↓
Executes all commands together
```

This reduces communication overhead between:

* Jenkins controller
* Jenkins agent

# Important CI/CD Engineering Practice

In production pipelines:

* shell commands are usually grouped logically
* related operations stay together
* pipelines become easier to debug

Example:

```groovy id="4ozvjp"
sh '''
npm ci
npm test
npm run build
'''
```

instead of:

```groovy id="sh2c6r"
sh 'npm ci'
sh 'npm test'
sh 'npm run build'
```

---

# Important Difference: Shell State Persistence

A major advantage of multiline `sh` blocks is that shell state persists inside the same session.

Example:

```groovy id="sdr4k5"
sh '''
cd app
ls
'''
```

works because:

* `cd app` affects subsequent commands in the same shell

But this fails:

```groovy id="26icab"
sh 'cd app'
sh 'ls'
```

because every `sh` starts a new shell session.

This is extremely important in Jenkins Pipelines.

# The Reality of Jenkins

A Jenkins pipeline is usually small.

Example:

```groovy id="4p68w5"
pipeline {
    agent any

    stages {
        stage('Build') {
            steps {
                sh 'npm ci'
                sh 'npm test'
            }
        }
    }
}
```

Writing this takes minutes.

Making it reliable in production may take hours or days.

# Important Debugging Lessons

## 1. Syntax Errors Happen Frequently

Example:

```groovy id="v8w9y7"
stages {
    stage('Build') {
        steps {
            sh 'npm ci'
```

Missing closing braces:

```groovy id="2k4w4n"
}
}
}
```

causes Jenkins pipeline parsing failure.

---

# What Jenkins Usually Shows

Typical error:

```text id="db8pba"
WorkflowScript: 27: expecting '}', found ''
```

This means:

* Jenkins parser reached line 27
* it expected a closing brace
* but structure was incomplete

Important:

The reported line is not always where the actual mistake is.

Sometimes the real problem happened several lines earlier.

---

# Why Indentation Matters

Groovy technically does not require indentation.

But humans do.

Bad formatting:

```groovy id="igx4u9"
stages {
stage('Build') {
steps {
sh 'npm ci'
}
}
```

Hard to debug.

Good formatting:

```groovy id="v15rm6"
stages {
    stage('Build') {
        steps {
            sh 'npm ci'
        }
    }
}
```

Now mismatched braces become visually obvious.

# Pipeline Structure Hierarchy

Declarative pipelines follow a strict hierarchy:

```text id="17s6sl"
pipeline
 ├── agent
 ├── stages
 │    ├── stage
 │    │    ├── steps
 │    │    │    └── commands
 └── post
```

Common beginner mistakes:

| Mistake                     | Problem              |
| --------------------------- | -------------------- |
| `stage` instead of `stages` | invalid pipeline     |
| `step` instead of `steps`   | invalid syntax       |
| missing `{}`                | parser failure       |
| misplaced `post` block      | structure error      |
| using `sh` outside `steps`  | runtime/syntax issue |

---

# Jenkins Error Messages Are Often Indirect

This is important.

Jenkins frequently reports:

* where parsing finally failed
* not where the original mistake happened

Example:

```groovy id="pv2r7q"
steps {
    sh 'npm ci'

post {
```

The real problem:

```groovy id="znm2zd"
}
```

was missing before `post`.

But Jenkins may complain later in the file.

# Why Logs Matter

The console output is your primary debugging tool.

You must learn to read logs carefully.

A pipeline log tells you:

* which command executed
* execution order
* exit codes
* warnings
* environment values
* shell output
* timestamps
* failures

# Example of Real Debugging

Pipeline:

```groovy id="b20jcw"
sh 'docker build -t app .'
```

Error:

```text id="1vskj5"
permission denied while trying to connect to the Docker daemon socket
```

This is not a Jenkins syntax problem.

This is:

* Linux permissions
* Docker socket access
* Jenkins user configuration

Very common in DevOps.

---

# Compare Successful vs Failed Builds

Excellent troubleshooting technique.

Compare:

* previous successful build logs
* current failed build logs

Ask:

| Question                          | Purpose                |
| --------------------------------- | ---------------------- |
| What changed?                     | isolate issue          |
| Which command failed?             | identify failure point |
| Did environment variables change? | detect config drift    |
| Did dependencies update?          | version issue          |
| Did agent/container change?       | infrastructure issue   |

---

# Make Small Changes

Critical DevOps principle.

Bad approach:

* modify 20 things
* rerun pipeline
* fail
* now you don't know what caused it

Good approach:

1. make one small change
2. run pipeline
3. verify behavior
4. continue

This is iterative debugging.

# Real CI/CD Troubleshooting Categories

In production Jenkins systems, failures usually come from:

| Area                  | Common Issues                     |
| --------------------- | --------------------------------- |
| Git                   | authentication, branch missing    |
| Docker                | permissions, image build failures |
| Kubernetes            | kubeconfig, RBAC                  |
| Maven/npm             | dependency resolution             |
| AWS                   | IAM permissions                   |
| Jenkins agents        | disconnected nodes                |
| Environment variables | missing secrets                   |
| Networking            | DNS/firewall/proxy                |
| File permissions      | Linux ownership issues            |
| Disk space            | workspace exhaustion              |
| Plugins               | version incompatibilities         |

# Most Valuable Jenkins Skill

Not syntax memorization.

The most valuable skill is:

1. reading logs carefully
2. isolating failures
3. understanding execution flow
4. reproducing issues
5. making controlled changes
6. validating assumptions

That is what separates reliable DevOps engineers from people who only copy pipeline examples.

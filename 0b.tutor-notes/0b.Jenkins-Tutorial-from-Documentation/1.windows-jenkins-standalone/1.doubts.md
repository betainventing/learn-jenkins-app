In a Windows 11 Pro environment, the command:

```powershell
java -jar jenkins.war --httpPort=8080
```

starts Jenkins as a standalone Java application using the embedded web server included inside `jenkins.war`.

Since you already have:

* Java 21 installed
* Docker Desktop installed
* Windows 11 Pro

you already meet the major prerequisites for running Jenkins locally.

---

# What This Command Does in Windows

## Full Command

```powershell
java -jar jenkins.war --httpPort=8080
```

Breakdown:

| Part              | Meaning                                       |
| ----------------- | --------------------------------------------- |
| `java`            | Starts the Java Runtime                       |
| `-jar`            | Tells Java to run a packaged Java application |
| `jenkins.war`     | Jenkins application archive                   |
| `--httpPort=8080` | Jenkins listens on TCP port 8080              |

---

# Step-by-Step Internal Execution on Windows

---

# 1. Windows Starts `java.exe`

When you run:

```powershell
java -jar jenkins.war
```

Windows searches for:

```text
java.exe
```

through the system `PATH`.

Usually located in:

```text
C:\Program Files\Java\jdk-21\bin\
```

or:

```text
C:\Program Files\Eclipse Adoptium\jdk-21\bin\
```

You can verify:

```powershell
where java
```

Example:

```text
C:\Program Files\Java\jdk-21\bin\java.exe
```

---

# 2. JVM (Java Virtual Machine) Starts

Windows creates a new process:

```text
java.exe
```

Inside that process, JVM initializes:

* Heap memory
* Garbage collector
* JIT compiler
* Threads
* Class loaders

You can see it in:

## Task Manager

```text
Task Manager → Details → java.exe
```

or:

```powershell
Get-Process java
```

---

# 3. Jenkins WAR File Is Loaded

The JVM opens:

```text
jenkins.war
```

A `.war` file is:

```text
Web Application Archive
```

Internally it contains:

* Jenkins core
* Web UI
* Embedded Winstone servlet container
* Plugins framework
* REST APIs
* Authentication modules

Think of it as:

```text
A complete portable Jenkins server in one file
```

---

# 4. Embedded Web Server Starts

Jenkins does NOT require IIS or Apache on Windows.

The WAR contains an embedded servlet container called:

```text
Winstone
```

Winstone behaves similarly to:

* Tomcat
* Jetty

but is bundled inside Jenkins.

When Jenkins starts:

```text
java.exe
   ↓
Winstone starts
   ↓
HTTP listener opens
```

---

# 5. Port 8080 Is Opened

This option:

```powershell
--httpPort=8080
```

tells Jenkins:

> Listen for HTTP traffic on TCP port 8080.

Windows networking stack creates:

```text
0.0.0.0:8080
```

Meaning:

```text
All network interfaces on port 8080
```

---

# Verify Port Binding in Windows

Open PowerShell:

```powershell
netstat -ano | findstr :8080
```

Example:

```text
TCP    0.0.0.0:8080     0.0.0.0:0     LISTENING     1234
```

Where:

| Field          | Meaning                     |
| -------------- | --------------------------- |
| `0.0.0.0:8080` | Listening on all interfaces |
| `LISTENING`    | Waiting for connections     |
| `1234`         | Process ID                  |

Check process:

```powershell
tasklist | findstr 1234
```

---

# 6. Jenkins Home Directory Created in Windows

On first startup Jenkins creates:

```text
C:\Users\<YOUR-USERNAME>\.jenkins
```

Example:

```text
C:\Users\Admin\.jenkins
```

This is extremely important.

It stores:

| Directory/File | Purpose             |
| -------------- | ------------------- |
| jobs\          | Jenkins jobs        |
| plugins\       | Installed plugins   |
| workspace\     | Build workspaces    |
| users\         | User accounts       |
| secrets\       | Encryption keys     |
| config.xml     | Main Jenkins config |
| logs\          | Logs                |

---

# First Startup in Windows

When Jenkins starts first time:

It generates:

```text
initialAdminPassword
```

Location:

```text
C:\Users\<USERNAME>\.jenkins\secrets\initialAdminPassword
```

Read it:

```powershell
Get-Content $env:USERPROFILE\.jenkins\secrets\initialAdminPassword
```

You paste this password into:

```text
http://localhost:8080
```

# Running Jenkins with More Memory

Java 21 allows tuning JVM memory.

Example:

```powershell
java -Xms1G -Xmx2G -jar jenkins.war --httpPort=8080
```

Meaning:

| Option   | Meaning            |
| -------- | ------------------ |
| `-Xms1G` | Initial heap = 1GB |
| `-Xmx2G` | Maximum heap = 2GB |

Useful because Jenkins can become memory-heavy with plugins.

# Common Windows Problems

---

# Problem 1 — Port 8080 Already Used

Error:

```text
Failed to listen on port 8080
```

Check:

```powershell
netstat -ano | findstr :8080
```

Use another port:

```powershell
java -jar jenkins.war --httpPort=9090
```

---

# Problem 2 — Java Not Found

Error:

```text
'java' is not recognized
```

Meaning:

* Java not in PATH

Fix:

Add:

```text
C:\Program Files\Java\jdk-21\bin
```

to Windows Environment Variables → PATH.

---

# Problem 3 — Windows Firewall Blocking

Windows Defender Firewall may ask:

```text
Allow Java through firewall?
```

Allow access for:

* Private network

Otherwise browser access may fail.

---

# Problem 4 — Long Startup Time

Normal on first startup.

Because Jenkins downloads:

* Suggested plugins
* Metadata
* Update center info

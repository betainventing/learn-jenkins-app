## what is java runtime?

Java Runtime means:

> The environment required to execute Java applications.

It provides everything needed to run compiled Java code on a system.

---

# Simple Definition

When you run:

```bash id="e9e7xv"
java -jar jenkins.war
```

the Java Runtime:

* Loads Java bytecode
* Starts the JVM
* Allocates memory
* Executes instructions
* Manages threads
* Performs garbage collection

Without a Java Runtime, Java applications cannot run.

---

# Real Meaning of “Runtime”

A program has two major phases:

| Phase        | Meaning                                    |
| ------------ | ------------------------------------------ |
| Compile time | Source code → machine-independent bytecode |
| Runtime      | Actual execution of the program            |

Java Runtime refers to the execution environment during runtime.

---

# Java Execution Flow

Java programs do NOT run directly from source code.

Flow:

```text id="pvrcr9"
Java Source Code (.java)
        │
        ▼
Java Compiler (javac)
        │
        ▼
Bytecode (.class)
        │
        ▼
Java Runtime
        │
        ▼
JVM executes bytecode
```

---

# Core Components of Java Runtime

Java Runtime mainly consists of:

| Component         | Purpose             |
| ----------------- | ------------------- |
| JVM               | Executes bytecode   |
| Core Libraries    | Java APIs           |
| Class Loader      | Loads classes       |
| Garbage Collector | Memory cleanup      |
| JIT Compiler      | Optimizes execution |

---

# 1. JVM (Java Virtual Machine)

The JVM is the core execution engine.

It:

* Reads Java bytecode
* Converts bytecode into native machine instructions
* Executes instructions on Windows/Linux/macOS

Without JVM:

```text id="dl0sg9"
.class files cannot execute
```

---

# JVM Analogy

Think of JVM as:

```text id="fca4gv"
A virtual computer inside your real computer
```

Your Windows machine runs:

```text id="4j5f7i"
Windows → JVM → Java Application
```

---

# 2. Java Core Libraries

Java Runtime includes standard libraries like:

| Package     | Purpose                 |
| ----------- | ----------------------- |
| `java.lang` | Basic language features |
| `java.io`   | File handling           |
| `java.net`  | Networking              |
| `java.sql`  | Database access         |
| `java.util` | Collections/utilities   |

Jenkins heavily uses these libraries.

Example:

```java id="v0w5kh"
import java.io.File;
import java.net.Socket;
```

These APIs come from the Java Runtime.

---

# 3. Class Loader

Java programs are made of classes.

The Class Loader:

* Finds `.class` files
* Loads them into memory
* Links dependencies dynamically

When Jenkins starts:

```text id="rwvwxz"
Thousands of classes are loaded
```

including:

* Jenkins core
* Plugins
* Servlet classes
* Security modules

---

# 4. Garbage Collector (GC)

Java automatically manages memory.

The Garbage Collector:

* Detects unused objects
* Frees memory automatically

Without GC:

* Java applications would leak memory quickly

Jenkins creates many temporary objects during:

* Builds
* Plugin execution
* API requests
* UI rendering

GC continuously cleans them.

---

# 5. JIT Compiler (Just-In-Time Compiler)

Initially JVM interprets bytecode.

Then JIT:

* Detects frequently executed code
* Compiles it into native machine code
* Improves performance

This is why long-running Java apps become faster over time.

# Difference Between JDK, JRE, and JVM

This confuses many beginners.

---

# JVM

JVM is only:

```text id="0efy7d"
Execution engine
```

It runs Java bytecode.

---

# JRE (Java Runtime Environment)

JRE =

```text id="n3w2a9"
JVM + Libraries + Runtime Components
```

Used only to RUN Java applications.

---

# JDK (Java Development Kit)

JDK =

```text id="8vjlwm"
JRE + Development Tools
```

Includes:

| Tool      | Purpose                 |
| --------- | ----------------------- |
| `javac`   | Java compiler           |
| `java`    | Runtime launcher        |
| `javadoc` | Documentation generator |
| `jdb`     | Debugger                |

---

# Important Modern Java Change

Starting from Java 9+:

Oracle and OpenJDK distributions changed packaging.

Modern JDKs already include the runtime.

So when you installed Java 21:

you effectively installed:

```text id="k8s6r5"
JDK + Runtime
```

That is why Jenkins works immediately.

# Why Jenkins Requires Java Runtime

Jenkins itself is written in Java.

Its components:

* Core server
* Plugin system
* Pipelines
* Executors
* APIs

are Java bytecode.

Without Java Runtime:

```text id="8mwhh1"
jenkins.war is just a file
```

The runtime gives it execution capability.

---

# Important Detail About Cross-Platform Support

Java Runtime enables:

```text id="cnjd7n"
Write Once, Run Anywhere
```

Meaning the same Jenkins WAR runs on:

* Windows
* Linux
* macOS

because each OS has its own JVM implementation.

# Very Important Understanding

The command:

```powershell id="z0c6h5"
java -jar jenkins.war
```

does NOT mean:

```text id="gqf7j4"
Windows directly runs Jenkins
```

Instead:

```text id="5q75b2"
Windows runs Java Runtime
Java Runtime runs Jenkins
```

That distinction is fundamental in Java architecture.

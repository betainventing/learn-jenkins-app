# Jenkins in Historical Context

Jenkins is one of the most influential tools in the history of DevOps and CI/CD.

Originally:

* Started as Hudson in 2004
* Later became Jenkins after project governance changes

At the time, automated CI/CD pipelines were far less common and far less mature.

Jenkins helped standardize:

* Automated builds
* Automated testing
* Continuous integration workflows

across software engineering teams worldwide.

---

# Why Jenkins Became So Popular

At the time Jenkins emerged, many teams still:

* Built software manually
* Deployed manually
* Ran tests inconsistently

Jenkins introduced reliable automation for:

* Build execution
* Scheduled jobs
* Test orchestration
* Deployment pipelines

This was a major operational improvement.

---

# The Plugin Ecosystem

One of Jenkins’ biggest strengths became:

* Massive plugin ecosystem

Jenkins could integrate with:

* Git
* Docker
* Kubernetes
* AWS
* Slack
* Maven
* SonarQube
* Artifactory
* Thousands of other tools

This flexibility made Jenkins:

* Extremely adaptable
* Widely adopted in enterprises

---

# Why Jenkins Still Exists Everywhere

Many organizations still use Jenkins because:

* Huge installed base
* Mature ecosystem
* Deep customization
* Existing enterprise pipelines
* Internal tooling built around it

In many companies:

* Jenkins remains core production infrastructure

especially in:

* Legacy enterprise environments
* Large on-premise systems
* Highly customized CI/CD workflows

---

# But the Industry Evolved

Modern software development changed significantly after Jenkins became dominant.

Major shifts included:

* Git-centric workflows
* Cloud-native infrastructure
* Containers
* Kubernetes
* SaaS development platforms
* Developer experience focus

New CI/CD platforms were designed around these newer workflows from the beginning.

# YAML Pipelines vs Groovy Pipelines

Modern CI/CD platforms usually define pipelines using:

* YAML

Example technologies:

* GitHub Actions YAML
* GitLab CI YAML

---

# Why YAML Became Popular

YAML is generally:

* More declarative
* Simpler syntax
* Easier to read
* Easier for beginners

Compared to:

* Jenkins Groovy pipelines

---

# Jenkins Pipeline Complexity

Jenkins pipelines often involve:

* Groovy scripting
* Plugin-specific syntax
* Scripted/declarative pipeline models
* Jenkins-specific behavior

This provides flexibility but increases complexity.

# Security Discussion

The lecture correctly points out a major Jenkins reality:

```text id="’wini252"
Self-Hosted Jenkins Requires Continuous Maintenance
```

This includes:

* Jenkins core updates
* Plugin updates
* Security patches
* Dependency management

---

# Why Jenkins Security Is Hard

Jenkins installations commonly accumulate:

* Many plugins
* Custom scripts
* Long-lived credentials
* Legacy configurations

This increases:

* Operational burden
* Security exposure

---

# Managed Platform Advantage

Managed platforms like:

* GitHub
* GitLab

handle much of the platform maintenance automatically.

The provider manages:

* Security patching
* Infrastructure updates
* Platform hardening
* Availability

This reduces operational overhead significantly.

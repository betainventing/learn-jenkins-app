### Jenkins Pipeline from Git — Key Steps (Clean Notes)

---

### 1. Create Pipeline Definition File

* Create a file named **`Jenkinsfile`** at the **root of the repository**
* This file contains the pipeline definition (Groovy syntax)

---

### 2. Add Pipeline Code

* Copy a sample pipeline from Jenkins UI or documentation
* Paste into `Jenkinsfile`
* Save the file

---

### 3. Git Workflow (Mandatory)

After modifying `Jenkinsfile`:

```bash
git add Jenkinsfile
git commit -m "edit Jenkinsfile"
git push
```

Key points:

* Commit = local change recorded
* Push = send changes to remote repo (GitHub)
* Jenkins only reads from remote → push is required

---

### 4. Verify in GitHub

* Repository should now contain:

  * `Jenkinsfile`
* Latest commit message visible

---

### 5. Create Jenkins Pipeline Job

In Jenkins UI:

1. **New Item**
2. Enter name (e.g., `Learn-Jenkins-app`)
3. Select **Pipeline**
4. Click **OK**

---

### 6. Configure Pipeline

#### Pipeline Type:

* Select: **Pipeline script from SCM**

#### SCM:

* Git

#### Repository URL:

* Paste GitHub repo URL

#### Credentials:

* Not required for public repo
* Required for private repo

#### Branch:

* Default in Jenkins: `master`
* Change to:

```bash
main
```

#### Script Path:

* Default:

```bash
Jenkinsfile
```

* Must match exact filename and location

---

### 7. Build Pipeline

* Click **Build Now**
* Jenkins performs:

  1. Clone repository
  2. Read `Jenkinsfile`
  3. Execute pipeline stages

---

### 8. Execution Logs

Logs show:

* Repository clone step (auto-added by Jenkins)
* Commit ID and message
* Pipeline stages execution

Example stages:

```groovy
stage('Hello') {
    steps {
        echo 'Hello World'
    }
}
```

---

### 9. Important Behavior

Pipeline lifecycle:

```
Edit Jenkinsfile → Commit → Push → Build Now
```

* Jenkins does **not** read local files
* Always pulls from Git repository

---

### 10. Manual vs Automated Trigger

Current approach:

* Manual: Click **Build Now**

Future (recommended):

* Webhook trigger from GitHub
* Automatic build on every commit

---

### Core Understanding

* Jenkinsfile = pipeline as code
* Git = source of truth
* Jenkins = execution engine
* SCM integration = bridge between them

---

### Key Insight

Jenkins always:

1. Pulls latest code from repo
2. Reads Jenkinsfile
3. Executes pipeline

It never depends on your local environment.

# Storing Pipelines in Git — “Pipeline as Code”

Until now, the Jenkins pipeline definition was written directly inside the Jenkins UI.

That approach is acceptable for:

* learning
* experimentation
* quick testing

But it has serious limitations in real environments.

---

# 1. Why Storing Pipelines Only in Jenkins Is a Problem

If the pipeline exists only inside Jenkins:

* there is no version history
* changes are difficult to track
* rollback becomes harder
* collaboration becomes messy
* pipeline configuration is tied to one Jenkins server

This violates one of the main DevOps principles:

> Infrastructure and automation should be treated as code.

---

# 2. Pipeline as Code

Modern Jenkins implementations use:

* a `Jenkinsfile`
* stored inside a Git repository

Example structure:

```text id="l4z9xe"
project/
├── src/
├── tests/
├── pom.xml
└── Jenkinsfile
```

The `Jenkinsfile` contains the pipeline definition.

Example:

```groovy id="4xq6yo"
pipeline {
    agent any

    stages {
        stage('Build') {
            steps {
                sh 'echo Building application'
            }
        }
    }
}
```

---

# 3. Benefits of Pipeline as Code

## Version Control

Every pipeline change is tracked by Git.

You can see:

* who changed the pipeline
* what changed
* when it changed

---

## Collaboration

Multiple developers can:

* review pipeline code
* improve automation
* submit pull requests

---

## Reproducibility

A new Jenkins server can recreate the same pipeline directly from Git.

---

## Rollback Capability

If a pipeline breaks:

* revert to an earlier commit

---

## Standardization

Pipelines become:

* reusable
* consistent
* portable

---

# 4. Role of Git

Git is the version control system that manages source code and pipeline code.

Git handles:

* commits
* branches
* merges
* history tracking
* collaboration workflows

---

# 5. Role of GitHub

GitHub is a cloud platform that hosts Git repositories.

GitHub provides:

* remote repository hosting
* collaboration
* pull requests
* issue tracking
* CI/CD integrations

In this workflow:

* source code will be stored in GitHub
* the `Jenkinsfile` will also be stored in GitHub

---

# 6. Jenkins + GitHub Integration

Typical workflow:

```text id="0myhh6"
Developer pushes code to GitHub
            ↓
Jenkins detects repository changes
            ↓
Jenkins downloads repository
            ↓
Jenkins reads Jenkinsfile
            ↓
Pipeline executes automatically
```

This is the foundation of modern CI/CD systems.

---

# 7. What Jenkins Actually Does

When integrated with GitHub, Jenkins can:

* clone repositories
* checkout branches
* read the `Jenkinsfile`
* execute pipeline stages
* report build status

Internally Jenkins often runs commands like:

```bash id="lt4nj9"
git clone https://github.com/example/project.git
```

---

# 8. Why GitHub Is Commonly Used

GitHub became extremely popular because:

* free public repositories
* simple collaboration model
* strong Git integration
* large ecosystem
* integration with DevOps tools

Other alternatives exist:

* GitLab
* Bitbucket
* self-hosted Git servers

But GitHub is commonly used for learning and industry projects.

---

# 9. Important DevOps Principle

The key concept here is:

> Pipelines are software too.

That means:

* they should be versioned
* reviewed
* tested
* maintained
* shared

exactly like application source code.

---

# 10. Big Picture

You are now moving from:

* manually configured Jenkins jobs

to:

* fully version-controlled automation

This transition is one of the major foundational steps in real-world DevOps workflows.

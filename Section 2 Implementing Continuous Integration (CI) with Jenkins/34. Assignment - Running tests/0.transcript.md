### Objective: Add **Test Stage** to Jenkins Pipeline

You need to implement a new stage that does:

1. Verify `build/index.html` exists
2. Run project tests using `npm test`

---

## 1. Important Constraint

* Tests must run **after build stage**
* Requires:

  * `node_modules` (from `npm ci`)
  * `build/` directory (from `npm run build`)

So your pipeline order:

```text
Build → Test
```

---

## 2. Check `index.html` Exists

Use a shell check:

```bash
test -f build/index.html
```

Behavior:

* Exit code `0` → file exists → success
* Exit code `1` → file missing → pipeline fails

---

## 3. Run Tests in CI Mode

Problem:

* `npm test` is interactive locally

Solution in Jenkins:

```bash
CI=true npm test
```

Why:

* Disables interactive mode
* Runs tests once and exits

---

## 4. Complete Test Stage

Add this stage after Build:

```groovy
stage('Test') {
    agent {
        docker {
            image 'node:18-alpine'
            reuseNode true
        }
    }
    steps {
        sh '''
        echo "Checking build output..."
        test -f build/index.html

        echo "Running tests..."
        CI=true npm test
        '''
    }
}
```

---

## 5. Full Pipeline (Build + Test)

```groovy
pipeline {
    agent none

    stages {
        stage('Build') {
            agent {
                docker {
                    image 'node:18-alpine'
                    reuseNode true
                }
            }
            steps {
                sh '''
                npm ci
                npm run build
                '''
            }
        }

        stage('Test') {
            agent {
                docker {
                    image 'node:18-alpine'
                    reuseNode true
                }
            }
            steps {
                sh '''
                test -f build/index.html
                CI=true npm test
                '''
            }
        }
    }
}
```

---

## 6. What Happens Internally

* Build stage:

  * Creates `node_modules/`
  * Creates `build/`

* Test stage:

  * Reuses workspace (because of `reuseNode true`)
  * Verifies `build/index.html`
  * Executes tests

---

## 7. Failure Conditions

Pipeline fails if:

* `build/index.html` not found
* Any test fails

This is expected and correct CI behavior.

---

## 8. Common Mistakes

❌ Running test before build
❌ Using `npm install` instead of `npm ci`
❌ Forgetting `CI=true` → pipeline hangs
❌ Not using same Docker image → version mismatch

---

## 9. Key Insight

You are validating two things:

```text
Build correctness → index.html exists  
Code correctness → tests pass
```

This is the foundation of CI.

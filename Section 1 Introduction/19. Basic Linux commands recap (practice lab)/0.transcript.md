This lab is introducing core Linux shell operations that are heavily used later in CI/CD pipelines, Jenkins jobs, Docker builds, and automation scripts.

# Key Linux Commands Used

## 1. Navigate Directories

### Move one level up

```bash
cd ..
```

### Show current directory

```bash
pwd
```

Example:

```bash
/home/user
```

---

# 2. Create a Directory

### Create `build` directory

```bash
mkdir build
```

### Verify with long listing

```bash
ls -l
```

You should see:

```bash
drwxr-xr-x ... build
```

---

# 3. Create a File with Content

### Create `computer.txt` containing `mainboard`

```bash
echo "mainboard" > build/computer.txt
```

### Check contents

```bash
cat build/computer.txt
```

Output:

```bash
mainboard
```

---

# 4. Overwrite vs Append

## Overwrite (`>`)

```bash
echo "display" > build/computer.txt
```

This replaces existing contents.

File becomes:

```text
display
```

---

## Append (`>>`)

Restore:

```bash
echo "mainboard" > build/computer.txt
```

Append:

```bash
echo "display" >> build/computer.txt
```

Now file contains:

```text
mainboard
display
```

This distinction is critical in scripting and pipelines.

* `>` = overwrite file
* `>>` = append to file

---

# 5. Test if File Exists

### Check whether file exists

```bash
test -f build/computer.txt
```

No output is normal.

Linux commands communicate success/failure using exit codes.

### Show exit code

```bash
echo $?
```

---

## Exit Codes

| Exit Code | Meaning |
| --------- | ------- |
| 0         | Success |
| 1         | Failure |

Example:

```bash
test -f build/computer.txt
echo $?
```

Output:

```bash
0
```

Meaning:

* File exists
* Command succeeded

---

## Non-existing File

```bash
test -f build/info.txt
echo $?
```

Output:

```bash
1
```

Meaning:

* File not found
* Command failed

This is exactly how CI/CD pipelines determine whether a build step passed or failed.

---

# 6. Search Inside Files Using `grep`

### Search for `display`

```bash
grep "display" build/computer.txt
```

Output:

```text
display
```

---

## Search for Missing Text

```bash
grep "keyboard" build/computer.txt
echo $?
```

Output:

```bash
1
```

Meaning:

* Pattern not found

Again, this behavior is extremely important in Jenkins pipelines and shell scripting.

# What This Lab Actually Teaches

This is not just “basic Linux.”

These are foundational operations used everywhere in DevOps:

| Operation    | Real DevOps Usage                       |
| ------------ | --------------------------------------- |
| `cd`         | Navigate build/work directories         |
| `mkdir`      | Create artifacts/log/temp directories   |
| `echo`       | Generate config files dynamically       |
| `>` and `>>` | Write logs/configuration/build metadata |
| `cat`        | Inspect generated files                 |
| `test`       | Validate artifacts/files exist          |
| `grep`       | Verify output/configuration/logs        |
| `$?`         | Detect success/failure in automation    |

---

# Important CI/CD Concept

Most shell commands do not print:

* “Success”
* “Failure”

Instead, automation tools rely on:

* exit code `0`
* non-zero exit codes (`1`, `2`, etc.)

Example in Jenkins:

```bash
grep "SUCCESS" output.log
```

If grep fails:

* exit code becomes `1`
* Jenkins stage fails automatically

That is why understanding exit codes is mandatory for DevOps and Linux automation.

# Passing Dynamic Runtime Data Between Pipeline Stages

The core problem is:

Netlify staging deployments generate random URLs dynamically.

Example:

```text id="jlwm01"
https://random-preview-id--app.netlify.app
```

That URL changes every deployment. 

So the pipeline cannot hardcode:

```text id="jlwm02"
CI_ENVIRONMENT_URL=https://something.netlify.app
```

because staging URLs are ephemeral.

---

# The Goal

The pipeline wants to do:

```text id="jlwm03"
Deploy staging
    ↓
Extract generated staging URL
    ↓
Pass URL to Playwright tests
    ↓
Run automated E2E tests against staging
```

This is a huge step toward fully automated deployment validation.

---

# Linux Output Redirection

The lecture then explains:

>

# Standard Output

Example:

```bash id="jlwm13"
echo hello
```

prints to:

# STDOUT (standard output)

---

# Redirect Operator

Example:

```bash id="jlwm14"
echo hello > hello.txt
```

means:

```text id="jlwm15"
Take stdout
    ↓
Write into file
```

instead of terminal.

---

# Important Difference

## Overwrite

```bash id="jlwm16"
>
```

overwrites file.

---

## Append

```bash id="jlwm17"
>>
```

appends to existing file.

Very important Linux distinction.

# What jq Does

`jq` allows querying JSON structures.

Example:

```bash id="jlwm22"
jq '.deploy_url'
```

Meaning:

```text id="jlwm23"
Extract deploy_url property
```

---

# Why jq Is Widely Used

`jq` is heavily used in:

* Kubernetes automation
* AWS CLI scripting
* Terraform pipelines
* GitHub Actions
* shell scripting
* CI/CD parsing

because modern infrastructure tools emit JSON extensively.

---

# Node Wrapper

They install:

```bash id="jlwm24"

```

because project already uses Node.js ecosystem.

So instead of system package manager:

```bash id="jlwm25"

```

they use Node wrapper for portability.

---

# Final Parsing Command

Conceptually:

```bash id="jlwm26"
node-jq -r '.deploy_url' deploy-output
```

Meaning:

| Part          | Purpose           |
| ------------- | ----------------- |
| node-jq       | JSON parser       |
| -r            | raw output        |
| '.deploy_url' | property selector |
| deploy-output | input file        |

---

# Why `-r` Matters

Without:

```bash id="jlwm27"
-r
```

jq returns quoted JSON strings:

```json id="jlwm28"
"https://..."
```

With `-r`:

```text id="jlwm29"
https://...
```

Much easier for shell scripting/environment variables.

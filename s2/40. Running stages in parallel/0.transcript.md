### Running Stages in Parallel in Jenkins Pipeline

---

## 1. Problem with Sequential Execution

Current flow:

```text
Checkout → Build → Unit Test → E2E Test → Reports
```

Issue:

* Each stage waits for the previous one
* Total time = **sum of all stages**

---

## 2. What Can Be Parallelized

These two stages are independent:

```text
Unit Test  
E2E Test
```

So instead of:

```text
Unit Test → E2E Test
```

We do:

```text
Unit Test  
     ↘
      Parallel
     ↗
E2E Test
```

---

## 3. How Jenkins Parallel Works

You must:

1. Create a **parent stage**
2. Use the keyword:

```groovy
parallel
```

---

## 4. Implementation

### Parallel Stage Structure

```groovy
stage('Run Tests') {
    parallel {

        stage('Unit Test') {
            agent {
                docker {
                    image 'node:18-alpine'
                    reuseNode true
                }
            }
            steps {
                sh '''
                npm ci
                npm test
                '''
            }
            post {
                always {
                    junit 'test-results/*.xml'
                }
            }
        }

        stage('E2E Test') {
            agent {
                docker {
                    image 'mcr.microsoft.com/playwright:v1.40.0-jammy'
                    reuseNode true
                }
            }
            steps {
                sh '''
                npm ci

                node_modules/.bin/serve -s build &
                sleep 10

                npx playwright test --reporter=html
                '''
            }
            post {
                always {
                    publishHTML([
                        reportDir: 'playwright-report',
                        reportFiles: 'index.html',
                        reportName: 'Playwright HTML Report'
                    ])
                }
            }
        }

    }
}
```

---

## 5. What Happens Internally

Jenkins does:

```text
Start Unit Test container
Start E2E Test container
Run both simultaneously
Wait for both to finish
```

You will see in logs:

* Interleaved output
* Two Docker containers running at same time

---

## 6. Pipeline Visualization

UI may still look linear, but:

Logs reveal:

```text
[Unit Test] npm test running...
[E2E Test] serve starting...
[Unit Test] completed
[E2E Test] running playwright...
```

→ This confirms parallel execution

## 7. Time Improvement

Before:

```text
Unit (30s) + E2E (60s) = 90s
```

After:

```text
max(30s, 60s) = 60s
```

---

## 8. Moving Post Actions (Best Practice)

Instead of global:

```groovy
post {
    always {
        junit ...
        publishHTML ...
    }
}
```

Use **stage-specific post blocks**:

### Unit Test

```groovy
post {
    always {
        junit 'test-results/*.xml'
    }
}
```

### E2E Test

```groovy
post {
    always {
        publishHTML(...)
    }
}
```

Benefit:

```text
Clear ownership of reports per stage
```

---

## 9. Important Considerations

### Workspace Sharing

* Both stages use same workspace
* Can cause:

  * File overwrite
  * Conflicts

Avoid by:

* Using different report directories

---

### Resource Usage

Parallel execution:

* Uses more CPU/RAM
* Requires capable agent

---

### Dependencies

Only parallelize if:

```text
No dependency between stages
```

Example:

* ❌ Build → Test (dependent)
* ✅ Unit Test + E2E (independent)

---

## 10. Common Mistakes

❌ Missing wrapper stage
❌ Wrong indentation
❌ Shared files overwritten
❌ Running dependent stages in parallel

## 12. Mental Model

```text
parallel {
    stage A
    stage B
}
```

=

```text
Run A and B at the same time
```

## 13. Real DevOps Usage

Parallel stages commonly used for:

```text
- Unit tests (multiple environments)
- Cross-browser testing
- Lint + security scan + tests
- Multi-service builds
```

## 14. Final Takeaway

* Use `parallel` for independent stages
* Wrap inside a parent stage
* Keep reports stage-specific
* Monitor resource usage

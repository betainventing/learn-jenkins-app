## Amazon S3 Overview

Amazon Web Services provides a storage service called Amazon S3.

S3 stands for **Simple Storage Service**.

It is an **object storage service** used to store and retrieve files over the internet.

Typical use cases:

* Static website hosting
* Backup storage
* Log storage
* Media storage
* CI/CD artifact storage
* Data lakes

In DevOps workflows, S3 is commonly used because it is:

* Highly durable
* Scalable
* Globally accessible
* Easy to automate using CLI, SDKs, Jenkins pipelines, Terraform, etc.

---

## Core Concepts

### Bucket

A **bucket** is the top-level container in S3.

You can think of it as a very large folder.

Example:

```text
Bucket: learn-jenkins-20240518-1820
```

Rules:

* Bucket names must be globally unique across all AWS accounts
* Names are lowercase only
* No spaces
* Commonly use timestamps/random suffixes to ensure uniqueness

Example naming pattern:

```text
project-environment-date-time
```

Example:

```text
learn-jenkins-20240518-1820
```

---

### Object

Every file stored inside a bucket is called an **object**.

Examples:

```text
index.html
styles.css
app.js
logo.png
```

An S3 object consists of:

* File data
* Metadata
* Object key (path/name)

---

## Why S3 Fits Static Websites

A static website contains only frontend files:

* HTML
* CSS
* JavaScript
* Images

No backend runtime is required.

Since no server-side processing exists:

* No EC2 needed
* No database needed
* No application server needed

S3 can directly serve these files over HTTP/HTTPS.

Typical architecture:

```text
User Browser
      ↓
Amazon S3 Bucket
      ↓
Static Website Files
```

## Important Bucket Configuration Points

### Bucket Name Must Be Unique

S3 bucket names exist in a global namespace.

If another AWS customer already used the name:

```text
learn-jenkins
```

you cannot use it.

Common workaround:

```text
learn-jenkins-20240518-1820
```

---

### Region

Buckets are created in a specific AWS region.

Example regions:

* us-east-1
* ap-south-1
* eu-west-1

Region selection affects:

* Latency
* Compliance
* Pricing

---

### Default Settings Usually Left Enabled Initially

For beginner/static website setups, most defaults remain unchanged:

* Block public access
* Bucket versioning disabled
* Encryption defaults
* ACL disabled

Later, public access settings are modified when enabling website hosting.

## DevOps Perspective

Manual uploads through the AWS console are not scalable.

Real DevOps workflows automate uploads using:

* AWS CLI
* Jenkins pipelines
* GitHub Actions
* Terraform
* Ansible
* SDKs

Typical automation flow:

```text
Developer Pushes Code
        ↓
Jenkins Pipeline Runs
        ↓
Build Static Files
        ↓
Upload Files to S3 Automatically
        ↓
Website Updated
```

This eliminates manual deployment work.

## Important Technical Detail

S3 is **not a traditional filesystem**.

It is an **object store**.

Meaning:

* No real directories internally
* "Folders" are logical prefixes
* Objects are accessed by keys

Example:

```text
images/logo.png
```

Internally this is just an object key string.

## Key DevOps Benefits of S3

### Durability

S3 durability target:

```text
99.999999999% (11 nines)
```

AWS replicates data automatically across multiple devices/facilities.

---

### Scalability

No need to:

* Resize disks
* Add storage servers
* Manage RAID
* Configure replication manually

AWS handles scaling automatically.

---

### Integration

S3 integrates with many AWS services:

* Amazon CloudFront
* AWS Lambda
* Amazon EC2
* AWS CodePipeline
* AWS IAM

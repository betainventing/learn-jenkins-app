# EC2 Web Server Setup with Nginx

This lecture demonstrates how to create an EC2 Linux server and configure it as a basic web server using NGINX on Amazon Web Services. 

---

# Goal

Create:

* EC2 virtual machine
* Install Nginx
* Start web server
* Access website through browser

This is a learning/demo setup, not a production-grade deployment. 

---

# Step 1 — Launch EC2 Instance

From AWS Console:

1. Search for EC2
2. Launch new instance

Example configuration:

| Setting       | Value             |
| ------------- | ----------------- |
| Name          | `my web server`   |
| OS            | Amazon Linux      |
| AMI           | Amazon Linux 2023 |
| Instance Type | `t2.micro`        |

`t2.micro` is Free Tier eligible. 

---

# SSH Key Pair

Instead of passwords, EC2 commonly uses SSH keys for authentication.

## Why SSH Keys?

Advantages over passwords:

* Strong cryptography
* Harder to brute-force
* Industry standard
* More secure remote access

SSH authentication works using:

* Public key → stored on server
* Private key → stored on your machine



---

# Create Key Pair

Example:

* Key name: `GitLab`
* Format: `.pem`

PEM format works with:

* OpenSSH
* Linux/macOS SSH clients
* Git Bash/OpenSSH on Windows

AWS downloads the private key locally while the EC2 instance stores the public key. 

---

# Network Settings

Important inbound rules:

| Protocol    | Purpose                |
| ----------- | ---------------------- |
| SSH (22)    | Remote terminal access |
| HTTP (80)   | Website access         |
| HTTPS (443) | Secure website access  |

Settings enabled:

* Allow SSH traffic from internet
* Allow HTTP traffic
* Allow HTTPS traffic



---

# Public IP

`Auto-assign Public IP` must be enabled.

Without a public IP:

* Browser cannot access server
* SSH from internet will fail



---

# Instance Health

After launch:

* Wait for `2/2 status checks passed`

This confirms:

* VM operational
* Networking functional
* OS responding

# Connect to Instance

AWS provides browser-based connection using EC2 Instance Connect.

Steps:

# Install Nginx

## Package Manager

Amazon Linux 2023 uses:

```bash id="7c6poh"
dnf
```

`dnf` is the successor to:

```bash id="s0c3qe"
yum
```

Used in:

* Amazon Linux
* Fedora
* CentOS
* RHEL-family systems



---

# Nginx Installation Command

```bash id="fc46af"
sudo dnf install nginx -y
```

Breakdown:

| Part      | Meaning                  |
| --------- | ------------------------ |
| `sudo`    | Run with root privileges |
| `dnf`     | Package manager          |
| `install` | Install package          |
| `nginx`   | Package name             |
| `-y`      | Auto-confirm prompts     |



---

# Start Nginx Service

Installing software does not automatically start it.

Start service:

```bash id="m9gltl"
sudo systemctl start nginx
```



---

# Enable Auto-Start on Boot

Enable service persistence:

```bash id="mo4g33"
sudo systemctl enable nginx
```

This ensures:

* Nginx starts automatically after reboot



---

# Verify Nginx Status

```bash id="v4os3n"

```

Expected output contains:

```text id="6edwud"
active (running)
```

This confirms:

* Service operational
* Web server active

# HTTPS Issue Explained

Browser initially tries:

```text id="3nptfr"
https://
```

But HTTPS was not configured.

Result:

* Browser security warning
* Connection failure

Solution:

* Use plain HTTP temporarily

```text id="8d9pcg"
http://
```



---

# Why HTTPS Fails

HTTPS requires:

* SSL/TLS certificate
* Web server SSL configuration

Without certificate:

* Browser cannot establish encrypted connection

Nginx is running correctly; only SSL is missing. 

---

# Expected Result

Browser displays default Nginx page:

```text id="6e4df4"
Welcome to nginx!
```

Meaning:

* EC2 reachable from internet
* Nginx installed correctly
* Port 80 accessible
* Security group configured properly

This section introduces deployment and cloud-based CI/CD using Amazon Web Services.

The project flow described is:

1. Build the website
2. Test the website
3. Deploy the website to the cloud
4. Automate the entire process through Jenkins

The explanation then answers an important question:

> Why use cloud platforms at all?

## 1. Scalability

Cloud platforms allow infrastructure to scale dynamically.

Instead of buying fixed hardware capacity, cloud resources can expand or shrink depending on traffic and workload.

Example:

* During high traffic events like Black Friday:

  * more compute resources,
  * more memory,
  * more instances,
  * and more bandwidth
    can be provisioned automatically.

When traffic drops:

* resources can scale down,
* reducing unnecessary cost.

This is one of the biggest advantages over traditional on-premise infrastructure.

In DevOps terms, this is closely related to:

* auto scaling,
* elasticity,
* load balancing,
* and infrastructure automation.

## 2. Cost Efficiency

Traditional infrastructure requires:

* purchasing servers,
* maintaining hardware,
* cooling,
* electricity,
* networking,
* and operational staff.

Cloud providers shift this into a usage-based model.

You typically pay for:

* compute time,
* storage,
* bandwidth,
* databases,
* and managed services actually consumed.

The Black Friday example illustrates underutilization problems with physical infrastructure:

* peak traffic may require huge capacity,
* but most of the year the hardware sits mostly idle.

Cloud solves this by making infrastructure elastic instead of fixed.

## 3. Reliability and Availability

Major cloud providers operate globally distributed data centers with:

* redundancy,
* failover systems,
* backups,
* monitoring,
* and disaster recovery mechanisms.

Examples include:

* Amazon Web Services
* Microsoft Azure
* Google Cloud

Benefits:

* higher uptime,
* geographic redundancy,
* better disaster recovery,
* and enterprise-grade infrastructure.

This is why cloud services are commonly described as “highly available.”

## 4. Security

Large cloud providers invest heavily in:

* physical security,
* network security,
* identity management,
* compliance,
* encryption,
* and monitoring.

This does not automatically make applications secure, but it provides strong infrastructure-level security capabilities.

## Important Practical Point

The course explicitly says:

> The focus is not AWS-specific memorization.

The real objective is learning cloud deployment principles:

* infrastructure provisioning,
* deployment automation,
* CLI usage,
* CI/CD integration,
* credentials handling,
* environment management,
* and deployment workflows.

Once you understand these concepts in AWS, the same ideas transfer to:

* Microsoft Azure
* Google Cloud
* or other providers.

Only the tooling and service names change.

The DevOps principles remain mostly the same.

# Running CI Pipelines with Docker in Jenkins

This section introduces one of the most important modern CI/CD concepts:

> Using Docker containers as isolated build environments inside Jenkins pipelines.

This solves:

* missing tools
* dependency conflicts
* version management issues
* inconsistent build environments

---

# 1. The Initial Problem

The pipeline tries to run:

```bash id="5i2rzj"
npm --version
```

But Jenkins fails with:

```text id="t9rv6o"
npm: not found
```

This happens because:

* Jenkins agent is just a Linux machine
* npm is not part of standard Linux utilities

Commands like:

* `mkdir`
* `touch`
* `sleep`
* `echo`

already exist on most Linux systems.

But:

* `npm`
* `mvn`
* `gradle`
* `docker`
* `kubectl`

usually must be installed separately.

---

# 2. Understanding the Environment Problem

The instructor correctly explains an important DevOps issue.

Different projects require different runtime versions.

Example:

| Project    | Required Node Version |
| ---------- | --------------------- |
| Modern App | Node 18               |
| Legacy App | Node 10               |

Installing everything directly on Jenkins agents creates:

* dependency conflicts
* maintenance complexity
* inconsistent builds

This is a classic CI/CD challenge.

---

# 3. Traditional Solution vs Containerized Solution

## Option 1 — Install Tools Directly on Jenkins Agent

Example:

* install Node.js manually
* install npm manually

Problems:

* version conflicts
* hard maintenance
* polluted build servers
* scaling difficulties

---

## Option 2 — Use Docker Containers

Modern preferred approach.

Instead of modifying Jenkins agents:

* Jenkins launches temporary containers
* each container contains required tools
* containers are isolated

This is the industry-standard approach.

---

# 4. Docker as a Build Environment

Docker allows Jenkins to:

* dynamically create isolated environments
* run commands inside containers
* destroy environments afterward

Each project can use:

* its own OS image
* its own runtime
* its own dependencies

---

# 5. Pipeline Without Docker

Example stage:

```groovy id="a9g7pl"
stage('Without Docker') {
    steps {
        sh 'echo Without Docker'
    }
}
```

This executes directly on:

* Jenkins agent host OS

---

# 6. Pipeline With Docker

Example:

```groovy id="wd3kq8"
stage('With Docker') {
    agent {
        docker {
            image 'node:18-alpine'
        }
    }

    steps {
        sh 'npm --version'
    }
}
```

This changes execution completely.

Now Jenkins:

1. pulls Docker image
2. starts container
3. runs commands inside container
4. destroys container afterward

---

# 7. Understanding the Docker Image

Image used:

```text id="5q0vwt"
node:18-alpine
```

Breakdown:

| Part     | Meaning                       |
| -------- | ----------------------------- |
| `node`   | Official Node.js image        |
| `18`     | Node.js version               |
| `alpine` | Lightweight Alpine Linux base |

---

# 8. Why Alpine Images Are Popular

Alpine Linux is commonly used in CI/CD because:

* very small image size
* fast downloads
* fast startup
* lower storage usage

Ideal for ephemeral CI workloads.

---

# 9. Jenkins Docker Pipeline Plugin

The pipeline initially fails with:

```text id="slwvha"
invalid agent type "docker"
```

This is because Jenkins itself does not understand Docker syntax yet.

Remember:

> Jenkins core is minimal.

Functionality is added using plugins.

Required plugin:

* Docker Pipeline Plugin

This enables:

* `agent { docker { ... } }`
* Docker container integration in pipelines

---

# 10. Jenkins Plugin Architecture

Jenkins works like a plugin framework.

Core Jenkins is intentionally lightweight.

Features come from plugins:

* Git plugin
* Docker plugin
* Kubernetes plugin
* Maven plugin
* Blue Ocean plugin

This makes Jenkins:

* flexible
* extensible
* modular

But also:

* plugin-heavy
* sometimes complex to maintain

# 11. Syntax Errors in Pipelines

Several syntax mistakes occurred:

* misplaced colon
* missing quotes
* invalid structure

Example incorrect syntax:

```groovy id="9gjm6x"
image: node:18-alpine
```

Correct syntax:

```groovy id="1mq4h8"
image 'node:18-alpine'
```

Pipeline syntax is very sensitive.

Small formatting mistakes can produce confusing errors.

This is normal when learning Jenkins pipelines.

---

# 12. Why Quotes Matter

Incorrect:

```groovy id="b9z02r"
image node:18-alpine
```

Groovy interprets:

* `18-alpine` incorrectly
* subtraction-like parsing issues occur

Correct:

```groovy id="2l9s5h"
image 'node:18-alpine'
```

Quotes force interpretation as a string literal.

# 13. What Jenkins Actually Does Internally

The logs reveal internal Docker operations.

---

## Step 1 — Check Local Cache

```bash id="4d6lvo"
docker inspect
```

Checks whether image already exists locally.

---

## Step 2 — Pull Image

If image missing:

```bash id="m7xgri"
docker pull node:18-alpine
```

Downloads image from registry.

Usually from:
Docker Hub

---

## Step 3 — Start Container

```bash id="m3v7c1"
docker run
```

Starts temporary container.

---

## Step 4 — Execute Commands

Inside container:

```bash id="r6lyq0"
npm --version
```

Now npm exists because container already contains Node.js + npm.

---

## Step 5 — Destroy Container

Container stops after stage completes.

This provides:

* clean environment
* reproducibility
* isolation

---

# 14. Build Caching

First execution:

* image download required
* slower

Second execution:

* image already cached locally
* much faster

This explains:

* first run ≈ 56 seconds
* second run ≈ 4 seconds

---

# 15. Important CI/CD Concept — Ephemeral Environments

Containers in CI are usually:

* temporary
* disposable
* recreated repeatedly

This avoids:

* configuration drift
* environment pollution
* leftover artifacts

Modern CI systems heavily rely on ephemeral execution.

---

# 16. Why This Is Extremely Important

This approach enables:

* reproducible builds
* scalable CI systems
* project isolation
* multi-version support
* cloud-native pipelines

Without containers, CI systems become difficult to maintain at scale.

### Build Stage in Jenkins (Node.js Project)

---

### 1. What “Build” Means Here

* This project is not compiled (like Java/C++)
* Instead:

  * Minifies files
  * Optimizes assets
  * Prepares production-ready output

Command used:

```bash
npm run build
```

Result:

* Creates a **`build/`** directory (deployment-ready files) 
* Not stored in Git (artifact only)

---

### 2. Local Validation (Critical Step)

Before Jenkins:

```bash
npm run build
```

Expected:

* `Compiled successfully`
* `build/` directory created

Reason:

* Avoid debugging inside Jenkins
* Separate tool issues vs pipeline issues

---

### 3. Jenkins Pipeline — Build Stage

#### Stage Rename

```groovy
stage('Build')
```

---

### 4. Use Docker Agent (Node Environment)

Jenkins does not guarantee Node.js availability → use Docker:

```groovy
agent {
    docker {
        image 'node:18-alpine'
        reuseNode true
    }
}
```

Key points:

* `node:18-alpine` → lightweight Node.js image
* `reuseNode true` → reuse workspace

---

### 5. Commands Execution Block

```groovy
steps {
    sh '''
    ls -la
    node --version
    npm --version
    npm ci
    npm run build
    ls -la
    '''
}
```

---

### 6. Command Breakdown

#### `ls -la` (before)

* Verify initial state
* Confirms:

  * No `node_modules`
  * No `build`

#### `node --version`, `npm --version`

* Logs exact versions
* Useful for debugging reproducibility

#### `npm ci`

* Installs dependencies
* Uses `package-lock.json`
* Faster + deterministic (CI/CD optimized)

#### `npm run build`

* Executes production build
* Generates optimized files

#### `ls -la` (after)

* Confirms:

  * `node_modules/` created
  * `build/` directory created

---

### 7. Why `npm ci` instead of `npm install`

| Feature             | npm install    | npm ci          |
| ------------------- | -------------- | --------------- |
| Speed               | Slower         | Faster          |
| Lockfile strictness | Flexible       | Strict          |
| CI/CD usage         | Not ideal      | Designed for CI |
| Reproducibility     | Not guaranteed | Guaranteed      |

---

### 8. What Happens During Pipeline Execution

1. Jenkins clones repo
2. Starts Docker container (`node:18-alpine`)
3. Executes commands inside container
4. Installs dependencies
5. Runs build
6. Produces artifacts

---

### 9. Workspace Behavior

Before build:

```
(no node_modules)
(no build/)
```

After build:

```
node_modules/
build/
```

Artifacts exist only in:

* Jenkins workspace
* Not pushed to Git

---

### 10. Important Principle

**Never commit build artifacts to Git**

Reason:

* They are generated
* Large size
* Environment-specific

---

### 11. Full Minimal Jenkinsfile (Build Stage)

```groovy
pipeline {
    agent none

    stages {
        stage('Build') {
            agent {
                docker {
                    image 'node:18-alpine'
                    reuseNode true
                }
            }
            steps {
                sh '''
                ls -la
                node --version
                npm --version
                npm ci
                npm run build
                ls -la
                '''
            }
        }
    }
}
```

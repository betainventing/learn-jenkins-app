# ECS Cluster Creation — EC2 vs Fargate

The lecture introduces the starting point of working with Amazon Elastic Container Service:

* Creating an ECS cluster.

At first the ECS dashboard shows:

* `0 clusters`

meaning no container runtime environment exists yet.

---

# ECS Infrastructure Choice

When creating a cluster, ECS asks how containers should run.

Two primary launch types are available:

| Launch Type | Infrastructure Management |
| ----------- | ------------------------- |
| EC2         | You manage servers        |
| Fargate     | AWS manages servers       |

This decision is extremely important architecturally.

---

# Option 1 — ECS with EC2

Using ECS with Amazon Elastic Compute Cloud means ECS deploys containers onto EC2 virtual machines.

Architecture:

```text id="4d0t4s"
Docker Containers
    ↓
ECS
    ↓
EC2 Instances
```

---

# Advantages of EC2 Launch Type

You get:

* Full OS access
* SSH access
* Kernel-level control
* Custom networking flexibility
* Custom instance sizing

Useful for:

* Advanced workloads
* Specialized runtime requirements
* Cost optimization at scale

---

# Operational Responsibility with EC2

You must manage:

* OS patching
* Security updates
* Docker runtime
* Scaling
* Monitoring
* Troubleshooting
* Capacity management

This becomes operationally heavy.

---

# Option 2 — AWS Fargate

AWS Fargate abstracts away the servers entirely.

Architecture:

```text id="jlwmvl"
Docker Containers
    ↓
ECS
    ↓
Fargate
    ↓
AWS-managed infrastructure
```

You never directly interact with:

* EC2 instances
* Host operating systems
* Underlying servers

---

# What “Serverless” Actually Means

Serverless does NOT mean:

* No servers exist

It means:

* You do not manage the servers.

AWS manages:

* Provisioning
* Scaling
* Infrastructure maintenance
* Runtime environment

You focus only on:

* Containers
* Application behavior

---

# Why Fargate Is Beginner Friendly

Fargate removes many operational complexities:

| Removed Responsibility      | Managed by AWS |
| --------------------------- | -------------- |
| EC2 provisioning            | Yes            |
| OS maintenance              | Yes            |
| Cluster capacity management | Yes            |
| Infrastructure scaling      | Yes            |
| Host patching               | Yes            |

This significantly reduces troubleshooting complexity.

---

# Why This Matters for Learning

Using EC2-based ECS requires understanding:

* Linux administration
* Networking
* Capacity planning
* Docker host management
* Cluster operations

That can become overwhelming early in container learning.

Fargate allows focus on:

* Docker
* ECS concepts
* CI/CD workflows
* Deployment logic

instead of infrastructure debugging.

---

# Fargate Pricing

Important detail:

Fargate is generally NOT included in AWS Free Tier.

Billing is based on allocated resources:

* CPU
* Memory
* Storage
* Runtime duration

---

# Fargate Pricing Components

## 1. vCPU Allocation

Example from lecture:

* `0.25 vCPU`

This means:

* Quarter of a virtual CPU allocated to container workload.

---

# 2. Memory Allocation

Example:

* `0.5 GB RAM`

Container receives approximately:

* 512 MB memory

---

# 3. Storage

Example:

* `20 GB`

Used for:

* Writable container filesystem
* Temporary application data

---

# 4. Runtime Duration

Billing increases with:

* Total execution time

Example estimate:

* 1 hour runtime
* ~$0.38/month equivalent estimate for that usage scenario

The key point:

* Containers incur costs while running.

---

# Important Cloud Cost Principle

Even low-resource cloud services accumulate charges over time.

Typical beginner mistake:

```text id="32dg0d"
Create Service → Forget It Exists → Monthly Charges Continue
```

Because cloud resources remain allocated continuously.

---

# Why Fargate Is Still Worth Using

Despite cost:

* Simpler deployment
* Faster onboarding
* Less infrastructure complexity
* Cleaner developer experience

For learning ECS concepts, Fargate is often the fastest path.

# Key Architectural Difference

## Traditional EC2 Approach

You manage:

* Machines first
* Applications second

---

## ECS + Fargate Approach

You define:

* Application requirements

AWS manages:

* Infrastructure execution

This is one of the major principles behind modern cloud-native systems.

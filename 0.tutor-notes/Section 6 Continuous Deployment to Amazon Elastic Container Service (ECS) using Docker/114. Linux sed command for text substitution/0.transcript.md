# Removing the Last Manual Deployment Step

The pipeline was already highly automated:

* Build application
* Build Docker image
* Push image to Amazon Elastic Container Registry
* Deploy through Amazon Elastic Container Service

But one major problem still existed:

```text id="’wini216"
Task Definition Still Contained Hardcoded Image Version
```

---

# The Remaining Manual Problem

Inside the ECS task definition JSON:

```text id="’wini217"
...:1.0.113
```

was manually hardcoded.

Meaning:

* Every deployment required editing the JSON file manually.

This breaks true CI/CD automation.

---

# Why This Is a Problem

The Jenkins build number changes dynamically.

You cannot realistically:

* Predict future build numbers
* Manually synchronize versions continuously

This creates:

* Fragile deployments
* Human error risk
* Maintenance overhead

---

# Goal of the Final Automation Step

The objective becomes:

```text id="’wini218"
Build Number Generated Automatically
↓
Task Definition Updated Automatically
↓
Deployment Fully Automated
```

---

# Solution — Placeholder Replacement

Instead of hardcoding the version directly:

A placeholder is inserted into the task definition JSON.

Example conceptually:

```text id="’wini219"
__APP_VERSION__
```

This becomes:

* Search target

during pipeline execution.

---

# Why Placeholders Are Useful

Placeholders create:

* Template-style configuration

The actual value gets injected dynamically during runtime.

This is extremely common in:

* CI/CD
* Kubernetes manifests
* Terraform templating
* Helm charts
* Infrastructure automation

---

# Core `sed` Operation

The lecture uses:

* Substitution mode

Conceptually:

```text id="’wini221"
Find Placeholder
↓
Replace With Real Version
```

---

# General Sed Substitution Syntax

Structure:

```bash id="’wini222"
sed 's/old/new/g'
```

---

# Meaning of Each Part

| Part  | Purpose            |
| ----- | ------------------ |
| `s`   | Substitute         |
| `old` | Search pattern     |
| `new` | Replacement        |
| `g`   | Global replacement |

---

# Placeholder Replacement Example

Conceptually:

```bash id="’wini223"
sed 's/__APP_VERSION__/1.0.114/g'
```

This replaces:

* Every placeholder occurrence
  with
* Real build version

---

# Dynamic Variable Injection

Instead of static version:

```text id="’wini224"
1.0.114
```

the replacement uses:

```text id="’wini225"
$REACT_APP_VERSION
```

This makes deployments:

* Fully dynamic

---

# Why Quotes Matter

The command uses:

* Double quotes

because shell variables must expand.

Without correct quoting:

* Variable interpolation may fail

Shell quoting behavior is extremely important in scripting.

---

# Global Replacement Flag

The flag:

```text id="’wini226"
g
```

means:

* Replace all matches

not just:

* First occurrence

Useful safety mechanism.

---

# `-i` Flag — Edit In Place

The command also uses:

```bash id="’wini227"
-i
```

Meaning:

* Modify the file directly

Without `-i`:

* Output only prints to terminal

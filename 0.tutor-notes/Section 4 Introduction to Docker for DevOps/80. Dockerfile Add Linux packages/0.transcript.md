This lecture explains the correct production-oriented way to install Linux packages inside Docker-based Jenkins environments without running containers as root during pipeline execution.

This is a major improvement in both:

* security
* CI/CD architecture

```bash id="hwyj91"

```

# Critical Docker Caching Lesson

This is one of the most important technical parts of the lecture.

Initially:

```dockerfile id="m6xvwl"
RUN apt update
RUN apt install -y jq
```

looks fine.

But it creates a subtle caching problem.

---

# Why Separate `RUN` Instructions Can Be Dangerous

Docker caches layers independently.

Suppose:

```dockerfile id="cjs9ql"
RUN apt update
```

gets cached.

Later rebuild:

Docker may reuse cached package metadata.

Then:

```dockerfile id="81q4ub"
RUN apt install -y jq
```

uses stale package indexes.

Potential problems:

* package not found
* outdated packages
* inconsistent builds

This is a very important real-world Docker issue.

---

# Correct Pattern

Combine commands into single layer:

```dockerfile id="jlwmfu"
RUN apt update && apt install -y jq
```

Now:

* update and install happen together
* same layer
* same execution context
* no stale cache issue

This is standard Docker best practice.

---

# Important Linux `&&` Operator

In Linux:

```bash id="kjlwm7"
command1 && command2
```

means:

> execute command2 only if command1 succeeds

This is important for build safety.

---

# Why This Helps Docker Cache Correctly

If install command changes:

Docker invalidates entire combined layer.

Then:

```text id="h7if61"
apt update
```

runs again automatically.

This keeps package metadata fresh.

---

# Extremely Important Production Docker Pattern

Very common real-world pattern:

```dockerfile id="2n9p1r"
RUN apt-get update && \
    apt-get install -y jq curl wget && \
    rm -rf /var/lib/apt/lists/*
```

This:

* updates repositories
* installs packages
* cleans cache
* minimizes image size

Widely used in production images.

This lecture explains an important Docker concept:

> Docker images do not have to come from Docker Hub.

Many beginners incorrectly assume:

```text id="wzw0xt"
docker pull something
```

always downloads from [Docker Hub](https://hub.docker.com?utm_source=chatgpt.com).

That is not true.

Docker can pull images from many registries.

---

# Why `.NET` Images Look Different

The instructor searches for `.NET` images on Docker Hub and notices something unusual.

Unlike:

* Node.js
* Python
* PHP

the official Microsoft images are not primarily managed through Docker Hub.

Instead, Microsoft publishes container images through:

[Microsoft Artifact Registry (MCR)](https://mcr.microsoft.com?utm_source=chatgpt.com)

(Microsoft Container Registry)

---

# Important Docker Concept: Registries

A Docker registry is:

> a server that stores Docker images

Examples:

| Registry                                                                                      | Owner               |
| --------------------------------------------------------------------------------------------- | ------------------- |
| [Docker Hub](https://hub.docker.com?utm_source=chatgpt.com)                                   | Docker              |
| [GitHub Container Registry](https://ghcr.io?utm_source=chatgpt.com)                           | GitHub              |
| [Microsoft Artifact Registry](https://mcr.microsoft.com?utm_source=chatgpt.com)               | Microsoft           |
| [Amazon ECR](https://aws.amazon.com/ecr/?utm_source=chatgpt.com)                              | Amazon Web Services |
| [Google Artifact Registry](https://cloud.google.com/artifact-registry?utm_source=chatgpt.com) | Google              |

# Why `node:18` Works Without Full Path

When you write:

```bash id="n2g93m"
docker pull node:18
```

Docker automatically assumes:

```text id="72g5zc"
docker.io/library/node:18
```

which points to Docker Hub.

Docker Hub is the default registry.

That is why no fully qualified registry path is needed.

---

# Why Microsoft Images Need Full Paths

For Microsoft images, Docker must know:

* registry hostname
* repository path

Example:

```text id="0c33vw"
mcr.microsoft.com/dotnet/sdk:8.0
```

Breakdown:

| Part                | Meaning    |
| ------------------- | ---------- |
| `mcr.microsoft.com` | registry   |
| `dotnet/sdk`        | repository |
| `8.0`               | tag        |

Used only for:

Smaller image.


## ASP.NET Runtime

Used for web apps.

Example:

```bash id="14x6k5"

```

Includes ASP.NET runtime.

# Important Production Pattern

Very common Docker pattern:

## Build Stage

Use large SDK image:

```dockerfile id="4h5jgx"
FROM mcr.microsoft.com/dotnet/sdk:8.0
```

Compile application.

---

## Runtime Stage

Use smaller runtime image:

```dockerfile id="ch1cll"
FROM mcr.microsoft.com/dotnet/aspnet:8.0
```

Copy compiled application only.

This is called:

> multi-stage builds

Very important DevOps/container optimization concept.

# Key Takeaway From This Lecture

The most important lesson is:

> Docker Hub is not the entire Docker ecosystem.

Containers can come from many registries.

When an image includes:

```text id="mhn3r7"
registry/repository:tag
```

Docker knows exactly where to pull it from.

This is why:

```text id="mxq4hr"
node:18
```

looks simpler than:

```text id="rjuxkk"
mcr.microsoft.com/dotnet/sdk:8.0
```

because Docker Hub is the default registry while Microsoft uses its own registry infrastructure.

The transcript explains pipeline refactoring in Jenkins — specifically merging deployment stages and Playwright E2E testing stages into single logical stages to simplify the pipeline and reduce resource usage. 

Core idea:

* Previously:

  * deploy staging
  * staging E2E
  * deploy production
  * prod E2E

* New approach:

  * combine deployment + validation into one stage.

Reasoning:

* Deployment is not considered successful unless validation/tests pass.
* The stages are sequentially dependent anyway.
* No benefit from separating them if they always run together.

---

# Why merge stages?

Logical reason:

```text
deployment + validation = one operational unit
```

If deployment succeeds but Playwright tests fail:

```text
deployment should still be considered failed
```

Operational benefits:

* shorter pipeline visualization
* fewer Jenkins stages
* fewer container startups
* reduced CI resource consumption
* simpler maintenance

---

# Important Docker insight

Original setup:

* deployment stage:

  * generic Node.js container
* Playwright test stage:

  * Playwright Docker image

Observation:

* Playwright image already contains Node.js.

Verification:

```bash
node --version
```

Result:

* Playwright image uses Node 18.
* Therefore:

  * Netlify CLI can also run there.
  * Separate Node.js container becomes unnecessary.

This is a common CI/CD optimization pattern:

```text
use one capable tool image instead of multiple specialized images
```

# Resource optimization implication

Before merge:

```text
start container A
execute deployment
destroy container A

start container B
execute tests
destroy container B
```

After merge:

```text
start one container
deploy
test
destroy container
```

Benefits:

* fewer container initializations
* less image pulling
* lower pipeline latency
* lower CPU/RAM overhead
* less Jenkins orchestration work

Very relevant in:

* Kubernetes Jenkins agents
* Docker-in-Docker
* ephemeral CI runners

# Important operational concern

The transcript mentions deployment timing behavior:

```text
Netlify may acknowledge deployment before deployment is fully propagated
```

Meaning:

* deployment API response != application fully reachable

Possible issue:

```text
tests start too early
```

Potential mitigation:

```bash
sleep 5
```

or better:

```bash
retry health checks until available
```

Example:

```bash
curl -f https://app-url || retry
```

This is a real-world distributed systems issue:

* CDN propagation
* DNS propagation
* container startup delays
* ingress readiness
* cache invalidation

# Shell command substitution

Key syntax introduced:

```bash
VARIABLE=$(command)
```

Example:

```bash
MYVAR=$(date)
echo $MYVAR
```

This:

1. executes command
2. captures stdout
3. stores result into variable

Used for:

```bash
CI_ENVIRONMENT_URL=$(jq -r '.deploy_url' deploy-output.json)
```

Meaning:

* extract deploy URL
* assign to Playwright environment variable

---

# Important shell syntax rule

Correct:

```bash
VAR=value
```

Wrong:

```bash
VAR = value
```

Spaces break shell variable assignment.

---

# Why Playwright failed initially

Failure:

```text
Connection refused at localhost:3000
```

Reason:

* `CI_ENVIRONMENT_URL` was not available to Playwright.

Playwright config behavior:

```js
baseURL: process.env.CI_ENVIRONMENT_URL || "http://localhost:3000"
```

So if env variable is missing:

```text
fallback -> localhost:3000
```

But nothing was running locally.

---

# Important shell scope concept

Critical lesson from transcript:

This variable:

```bash
VAR=$(command)
```

exists only:

```text
inside the current shell/script process
```

It does NOT automatically propagate:

* across Jenkins stages
* across containers
* across separate shell invocations

This is one of the most common CI/CD beginner issues.

---

# Final working solution

They restored:

```groovy
environment {
    CI_ENVIRONMENT_URL = "placeholder"
}
```

Then updated it during execution.

Result:

* Playwright detects variable correctly
* tests execute against staging deployment
* merged stage works successfully

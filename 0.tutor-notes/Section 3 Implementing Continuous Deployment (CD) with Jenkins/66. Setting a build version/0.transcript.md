The lecture removes the manual approval gate and strengthens deployment validation using application versioning and automated end-to-end verification. 

---

# Core problem being solved

Previously:

* pipeline could potentially deploy stale artifacts
* old workspace contents could accidentally be reused
* deployment might succeed technically
* but wrong application version could reach production

This is a real-world CI/CD problem:

```text id="kgjlwm"
artifact drift
```

Meaning:

```text id="vr68b5"
what was deployed != what was intended
```

---

# Goal

Guarantee:

```text id="uhql5n"
the exact build generated by the current pipeline execution is the one running in production
```

---

# Build-time substitution

Inside React:

```js id="6h9cgj"
process.env.REACT_APP_VERSION
```

During build:

```text id="j8ol7n"
Webpack/Vite/build tooling replaces this with literal value
```

Example generated output:

```js id="xjxbw9"
Application version 1.2.3
```

This is:

```text id="mdyn8e"
compile-time injection
```

NOT runtime injection.

Important distinction.

# Critical Groovy/Jenkins string interpolation lesson

Single quotes:

```groovy id="jlwm7w"
'1.0.${BUILD_ID}'
```

DO NOT interpolate variables.

Literal string only.

Correct:

```groovy id="jlwm0g"
"1.0.${BUILD_ID}"
```

Double quotes enable:

```text id="jlwmzi"
Groovy string interpolation
```

Very common Jenkins mistake.

# Why this matters in production

Without deployment verification:

* stale Docker image may deploy
* old Kubernetes ReplicaSet may remain
* cached artifact may be reused
* wrong Git SHA may deploy
* rollback may silently occur
* CDN may serve outdated frontend

And pipeline may still appear:

```text id="jlwm3p"
green/successful
```

This is dangerous.

# Important architectural takeaway

The pipeline evolved from:

```text id="jlwm6q"
deploy and hope
```

toward:

```text id="jlwm0z"
deploy and cryptographically/logically verify
```

That transition is one of the major differences between:

* beginner CI/CD
* production-grade delivery systems

because:

```text id="jlwm9b"
successful deployment does not guarantee correct deployment
```

The lecture demonstrates how automated E2E validation can close that gap.

### Why the pipeline originally had a problem

Your pipeline was doing two conflicting things:

1. Creating useful output (`build/computer.txt`)
2. Deleting the workspace immediately afterward

So even though the build succeeded, the generated file was removed before Jenkins could preserve it.

That is why the artifact archiving failed.

---

# Key Concept: Artifact

An **artifact** is any file generated by the pipeline that should survive after the build finishes.

Examples:

* Compiled binaries (`.jar`, `.war`)
* Test reports
* Log files
* Docker image metadata
* Generated configuration files
* Your `computer.txt`

In your case:

```text
build/computer.txt
```

became the artifact.

---

# What `archiveArtifacts` Does

Inside a Jenkins Pipeline, this instruction:

```groovy
archiveArtifacts artifacts: 'build/**'
```

tells Jenkins:

> Preserve everything inside the `build` directory after the pipeline finishes.

---

# Meaning of `build/**`

The `**` is a wildcard pattern.

```groovy
build/**
```

means:

* include the `build` directory
* include all files
* include all subdirectories recursively

Example:

```text
build/
 ├── computer.txt
 ├── logs/
 │    └── output.log
 └── reports/
      └── report.html
```

All of these get archived.

---

# Why the Error Happened

Initially, your `post` section probably looked conceptually like this:

```groovy
post {
    always {
        cleanWs()
    }

    success {
        archiveArtifacts artifacts: 'build/**'
    }
}
```

The problem:

* `always` executes before `success`
* `cleanWs()` deletes the workspace
* then `archiveArtifacts` runs
* but the files are already gone

So Jenkins cannot archive anything.

---

# Important Jenkins Execution Order

Inside `post {}`:

1. `always`
2. `success` / `failure`
3. other conditions

So:

```groovy
always {
    cleanWs()
}
```

runs before:

```groovy
success {
    archiveArtifacts ...
}
```

That ordering caused the failure.

---

# Correct Solution

Instead of cleaning at the end:

* clean at the beginning
* archive after build success

This is the proper CI/CD approach in many pipelines.

---

# Corrected Pipeline Structure

Example:

```groovy
pipeline {
    agent any

    stages {

        stage('Clean Workspace') {
            steps {
                cleanWs()
            }
        }

        stage('Build') {
            steps {
                sh 'mkdir -p build'
                sh 'echo "mainboard" > build/computer.txt'
                sh 'echo "display" >> build/computer.txt'
                sh 'echo "keyboard" >> build/computer.txt'
            }
        }
    }

    post {
        success {
            archiveArtifacts artifacts: 'build/**'
        }
    }
}
```

---

# What Happens Now

## Step 1 — Clean Workspace

```groovy
cleanWs()
```

removes leftovers from previous builds.

This prevents stale files from polluting the new build.

---

## Step 2 — Build Runs

The pipeline creates:

```text
build/computer.txt
```

---

## Step 3 — Archive Happens

```groovy
archiveArtifacts artifacts: 'build/**'
```

Jenkins copies the files into Jenkins storage.

Now they are preserved permanently for that build.

---

# Result in Jenkins UI

After successful execution:

## Build Page

You see:

```text
Build Artifacts
```

Clicking it lets you download/view archived files.

---

## Workspace

The workspace still exists because you did not delete it afterward.

This helps with:

* debugging
* inspecting generated files
* troubleshooting failed builds

---

# Why Cleaning at the Beginning Is Usually Better

Advantages:

| Benefit                 | Explanation                        |
| ----------------------- | ---------------------------------- |
| Prevents stale files    | Old files cannot affect new builds |
| Artifacts survive       | Jenkins archives them safely       |
| Easier debugging        | Workspace still available          |
| More predictable builds | Each build starts clean            |

---

# Real DevOps Usage

In real CI/CD systems, artifacts commonly include:

* Maven `.jar` files
* Gradle outputs
* Docker image manifests
* Kubernetes manifests
* Terraform plans
* Test reports
* Security scan reports

These are archived so later pipeline stages or humans can use them.

Example:

```groovy
archiveArtifacts artifacts: 'target/*.jar'
```

for a Maven build.

---

# Core Lesson

The important lesson here is:

> Workspace files are temporary unless explicitly archived.

Jenkins workspaces are not permanent storage.

If something matters after the build finishes, archive it or publish it elsewhere.
